# 形状编辑环境与多列属性方案

2026-11-16。用户补充：88像素数值框应支持一行多个属性；物体允许多种形状，提供类似CAD的绘制环境，赋予属性后在场景内布置并进行物理模拟。同时保留已有场景的直接修改和实时调试，不要求重新绘制已有物体或重建场景。

本轮更新了九个属性面板原型，新增可交互的形状编辑原型，并单独验证Godot的凹形物体编译与原生碰撞。**正式Godot工作台尚未接入新编辑器和通用多边形。**

## 1. 两条入口，共用同一场景

```text
打开已有场景 → 选中已有物体/场景配置 → 直接修改属性或拖动布置 ─┐
                   └→ 编辑所选轮廓 → 校验 → 应用回原物体 ────┤
新建物体 → 绘制草图/选形状 → 校验 → 赋属性 → 加入当前场景 ───┘
    → 同一工作台预览/应用并运行 → 暂停检查/调整
    → 需要时重新录制Take → 渲染与声音 → 输出视频
```

分成两个可切换的编辑空间：

- **场景编辑是常规入口**：打开现有场景即可选物体，直接修改位置、角度、物理、外观和机制；背景、文字、声音等从场景面板修改。原有新建/打开/保存/另存为及应用并运行继续保留。
- **形状编辑是按需进入的工具**：新物体从空白/参数形状开始；已有物体从选中对象的局部轮廓开始。修改已有轮廓时先保存草稿，应用回同一对象ID，保留未修改的位置、旋转、物理/外观/机制属性和其他场景对象；放弃草稿不影响原对象。另设“保存为新物体副本”，不把修改原对象误做成新增对象。

一个形状可供多个物体复用；编辑共享形状必须说明影响范围，默认可复制为独立形状再修改。旧场景的内联circle/rectangle/line/arc等数据直接适配到编辑工具，不要求用户先手工转换为资产；新结构迁移保留ID、未编辑字段和资源引用。

用户可以手工画，也可由AI写结构化草图/命令；最终都经过同一套数据校验、编译和命令事务。不要维护一套“手绘数据”和另一套“AI数据”。

### 实时修改怎样生效

沿用当前工作台的行为；“实时”表示能在当前场景里修改并立即查看或重新试跑，不代表任意物理变化都能接着当前碰撞状态继续求解。

| 修改 | 应用方式 | 当前状态与接入要求 |
|---|---|---|
| 已支持的颜色、文字、渲染、声音、屏幕特效等表现参数 | 应用后更新预览；不改变物理轨迹时可复用Take | 当前已有此路径；新材质/背景/声音选项仍需逐项接入 |
| 初始位置、尺寸、质量、摩擦、弹性、机制、世界物理参数 | 同一场景内保存草稿，应用后重置初始布局；“应用并运行”直接从修改后的布局重新模拟 | 当前已有；不需要新建项目或重新摆放其他物体 |
| 已有物体的轮廓/碰撞形状 | 草稿校验、凸分解全部成功后原子替换；沿用应用/重新运行 | 本轮原型验证交互，正式工作台待接入；不在物理步中途替换碰撞体 |
| 录制轨迹后的物理/机制修改 | 保留旧Take，但标记过期；新轨迹需重新录制 | 当前会话保留旧Take；不把旧运动当作新参数的结果 |

当前实现依据：`workbench.gd::_after_command()`按`requires_reset`选择`load_document()`或`apply_presentation()`；`scene.apply_run`批量校验后应用并启动。新编辑器应复用CommandService、PendingEdits、撤销/重做、修订号及文件身份。运行中新生子球目前只读，继续编辑初始物体或生成规则，不将这一限制误写成任意运行时对象均可修改。

接入验收必须包含：打开旧场景直接改属性、选中已有物体改轮廓后ID/未改属性/其他对象不变、放弃不改原对象、跨页草稿保留、整批应用可一步撤销、保存重开有效，以及物理变化后Take过期。现有浏览器原型只验证其中的交互子集，没有接入真实场景文件或完整撤销系统。

原型还检查草稿冲突：若返回场景后又修改了同一个来源物体，旧轮廓草稿不能直接覆盖；提示放弃后重新编辑或保存新物体副本。正式接入复用现有修订号校验，避免UI与AI相互覆盖。

## 2. 一行多个属性，不留下大段空白

88像素只约束数字输入框，不意味着整行只放一个字段。按面板宽度放2～3个属性，标签置于各自输入框上方，单位放在标签或数值右侧。

```text
空间变换
X / px          Y / px          旋转 / °
[  448  ]       [  304  ]       [    0  ]

物理属性
质量            摩擦            弹性
[ 1.00  ]       [ 0.15  ]       [ 0.65  ]
```

分组规则：

| 属性 | 排列方式 |
|---|---|
| 位置/旋转 | X、Y、旋转同行；三维时X/Y/Z一行、旋转单独成组 |
| 尺寸 | 宽、高、厚度同行；圆显示半径/直径关联值，不存互相矛盾的两份尺寸 |
| 物理参数 | 质量、摩擦、弹性同行；阻尼、角阻尼、重力倍率另一行 |
| 范围/时间 | 上下限、淡入淡出等相关值相邻，不把无关参数硬塞同组 |
| 开关 | 两列；短标签配复选框，不独占一整行 |
| 颜色/短选项 | 与透明度、相邻颜色或短参数并排；长下拉框保留整行 |
| 路径/名称/文本 | 使用完整宽度；长名称和文件路径能查看完整内容 |

更新后的属性原型在390px检查器中以两列为主，单页520px预览采用三列；形状编辑器右侧把位置和物理常用值各放成一行三个。缩到320px时保持输入和标签不溢出。

## 3. 形状应支持到什么程度

| 形状类别 | 建议支持 | 碰撞生成方式 | 当前状态 |
|---|---|---|---|
| 基础形状 | 圆、矩形、胶囊、三角形、正多边形 | 原生参数形状或凸多边形 | 工作台已有圆/矩形；胶囊和通用多边形需扩展 |
| 自定义闭合形 | L形、U形、星形、任意简单凹多边形 | 凸分解后挂到同一刚体 | 本轮交互原型可画多边形；原生物理可行性验证通过，未接入工作台 |
| 开放线条/轨道 | 折线、曲线、导轨 | 必须有厚度；生成有面积的轮廓再编译 | 当前有有厚度的线段；通用折线/曲线编辑待实现 |
| 环和孔洞 | 圆环、扇区、带孔板 | 保留孔洞的实体分区，分别生成凸碰撞体 | 当前扇区玻璃仅静态；完整孔洞编辑与动态环待实现 |
| 组合物体 | 同一物体内多个互不相连的轮廓 | 多个碰撞体属于一个刚体 | 拟新增；默认不会自行散开 |
| 2.5D物体 | 草图沿厚度拉伸 | 同源生成可见网格和凸碰撞体组 | 拟新增；保持三维物理+正交镜头 |
| 3D模型 | 球、盒、柱、胶囊、自定义网格 | 原生形状/凸分解/适合静态的三角网格 | 当前工作台只接入球/盒，其余需扩展 |

第一批绘制工具：选择、移动、圆、矩形、闭合多边形、顶点编辑、网格吸附、精确坐标。随后加长度/角度输入、端点/中点/圆心吸附、缩放/平移、复制/阵列、对齐和图层锁定。

曲线应保留源控制点，再按可设的弦误差离散为轮廓，不能只画一条平滑曲线却使用粗糙的碰撞折线。SVG导入可后续增加，需要统一处理单位、变换、闭合路径和孔洞。

## 4. 凹形物体怎样保证物理正确

### 同一个物体，多个凸碰撞体

L形、U形不能直接取所有顶点的凸包；那样会把凹槽填满。正确路径是：

1. 校验源轮廓：有限坐标、至少3个有效顶点、边长/面积有效、无重复点、无自相交、绕序统一。
2. 使用Godot `Geometry2D.decompose_polygon_in_convex()` 将简单凹多边形拆为多个凸区域。
3. 每个区域生成一个 `ConvexPolygonShape2D`，全部放在**同一个** `RigidBody2D` 或 `StaticBody2D` 下。
4. 显示轮廓与碰撞体都由这份源几何生成，编辑时叠加显示实际编译的碰撞区域和误差。
5. 质量是整个刚体的质量，不给每片重复赋一份总质量。重心/惯性先使用原生求解器，再按需要提供显式覆盖。

多个凸区域只是求解器内部结构，不是破坏后的碎片。要让物体断开，必须通过独立破坏机制创建新的刚体，并定义质量、速度与生命周期规则。

孔洞不是普通单轮廓凸分解自动完成的功能：环形可以先按参数生成实体分区；任意带孔板需要显式保存外轮廓/内孔并采用能保留孔洞的分区流程。不能用凸包或连接孔洞边界后无条件填充。

二维动态物体优先使用凸分解后的实体形状。`ConcavePolygonShape2D` 的线段集合不宜作为通用动态实心刚体捷径；应按Godot的静态使用边界处理。开放路径必须设置厚度，不能把零面积线条当成有质量的实体。

非均匀缩放要烘焙进形状并重新编译，而非只缩放显示节点。运行中编辑源轮廓先保存草稿，应用后重建初始状态并重录轨迹，不能直接篡改正在碰撞的刚体。

### 本轮实际原生验证

独立工程运行 [native-shape-check.gd](design/inspector-20261116/native-shape-check.gd)，没有启动用户工作台或文件桥。Godot 4.7.2，120Hz，共360物理步。

| 检查 | 实测结果 |
|---|---|
| L形分解 | 2个凸区域；面积8000 → 8000 |
| U形分解 | 3个凸区域；面积25600 → 25600 |
| L形动态刚体落地 | 产生3次原生地面接触；该样本未穿过地板 |
| 小球进入U形内部 | 产生2次与U形的原生接触；最终球心Y≈468.15，进入凹槽并位于内底面Y=480上方 |
| 汇总 | 9项通过；报告见 [native-shape-validation.json](design/inspector-20261116/native-shape-validation.json) |

这证明基本几何/碰撞路径可用；尚未覆盖任意轮廓、高速/薄壁、数百物体、跨设备、完整Take或视频生产，不把一次样本验证称为工作台功能完成。

## 5. 赋予哪些物体属性

| 分组 | 字段方向 |
|---|---|
| 身份与几何 | 稳定ID、名称、标签、形状资产/版本、局部原点 |
| 场景变换 | 世界位置、旋转、尺寸/比例；2.5D额外厚度 |
| 物理 | dynamic/static/sensor、质量、初速度、角速度、摩擦、弹性、阻尼、CCD、碰撞分组 |
| 视觉 | 独立/共享材质、颜色、贴图、描边、发光、适用的三维PBR参数 |
| 声音 | 声学身份及对象对路由；与摩擦/弹性分开 |
| 机制 | 碰撞触发、计次耐久、破坏、传感器等；按形状能力校验可用组件 |

质量先直接输入；后续如加密度，明确质量/密度二选一，并按面积或体积及单位换算。修改形状后需重新计算自动质量/重心/惯性，避免仅改变显示。

当前分裂机制仅适用于圆/球。画成L形后不能自动套用“1→2小球”逻辑；应禁用不适用组件或明确选择“破坏成指定碎片”的新机制。UI不得展示一个可勾选但运行时静默不生效的选项。

原型保留分裂/破坏规划项用于说明组件范围；最终接入应补上述兼容校验，当前原型不执行这些机制。

## 6. 数据与架构接入

持久化以形状源数据为准：

```text
ShapeAsset：ID、版本、单位、参数/轮廓/控制点
ObjectSpec：形状引用、物理属性、材质引用、机制引用
Instance：场景内位置、角度、对象ID
CompiledShape：由源数据+编译版本生成的碰撞/显示缓存
Take：冻结所用形状版本、实际姿态、事件和生命周期
```

编译缓存不能成为第二份可随意修改的几何数据。修改共享形状要显示影响对象数，默认允许“复制为独立形状”。同一Take引用的几何须不可变，资产更新使依赖的物理轨迹过期。

建议接入点：

| 模块 | 改造内容 |
|---|---|
| SceneDocument / 形状校验 | 增加多边形/形状引用、版本迁移、轮廓约束、组件兼容校验；当前白名单只允许2D circle/rectangle/line/arc、3D sphere/box |
| ShapeCompiler | 原生形状创建、凸分解、轮廓误差、孔洞/薄壁限制、编译缓存；不含UI |
| World适配器 | 挂载同源生成的碰撞体；补动态与静态材质；不接受未经校验的任意轮廓 |
| 显示与拾取 | 按实际轮廓绘制、点在多边形判断；不能继续把新形状当矩形拾取 |
| 出生空间与机制 | 目前存在圆/盒特化路径；新增形状需完整更新，通用几何未接入前不开放任意分裂 |
| CommandService | shape.create/update、对象引用、场景布置批量提交；命令名称为方案，尚不是现有API |
| 编辑器 | 草稿顶点/拖动、吸附、选择/撤销；一次拖动形成一次事务，不把每个鼠标事件写入历史 |
| Take/生产 | 冻结形状资产、编译信息和材质资源；重放只恢复已记录状态 |

保持既有AI/界面共用CommandService、PendingEdits和初始场景/运行姿态分离的路线。本轮原型仅用于交互验证，没有绕过这些接口写入当前场景。

## 7. 已交付原型与落地批次

- [多列属性原型](design/inspector-20261116/index.html)：已更新九页布局和对应PNG，常规数值框88px，一行2～3个属性。
- [形状编辑原型](design/inspector-20261116/shape-editor.html)：圆/矩形拖绘，多边形点击闭合，顶点拖动，6种形状预设，属性赋值，加入场景、拖动布置、设计JSON导出。从属性面板入口默认显示已有示例场景；选物体后“编辑所选轮廓 → 应用回当前物体/放弃轮廓草稿”，无需重新创建物体。示例场景是内置演示，不是读取用户当前场景文件。
- [绘制环境预览图](design/inspector-20261116/10-shape-editor.png)、[场景布置预览图](design/inspector-20261116/11-scene-layout.png)。
- [原型检查](design/inspector-20261116/shape-editor-validation.json)覆盖绘制、拒绝自相交、改顶点、赋质量、实例独立、布置、已有物体原位更新/放弃草稿及真实宽度下的三列布局；不等于完整CAD手工可用性验收。

明确边界：原型的模拟入口禁用，导出JSON标为 `proposal_only`。当前工作台不能直接载入它。原生验证是另一独立工程的技术样本，没有形成“绘制后直接在正式工作台运行”的产品闭环。

建议分批落地：

1. **形状数据/编译与属性多列**：先把通用简单多边形、静态/动态材质、精确拾取、编辑撤销接入工作台；验证无效几何拒绝、凹槽保留、形状/显示一致。
2. **二维绘制到模拟闭环**：绘制/顶点编辑/吸附、资产复用、场景布置、运行暂停、保存重载、Take/生产；用L形、U形、星形、滑块/轨道进行真实录制导出验收。
3. **复杂轮廓与2.5D拉伸**：曲线、厚线、环/孔洞、组合物体和厚度；逐项验证碰撞误差、重心、惯性和薄壁CCD。
4. **三维扩展**：更多参数实体、网格导入和适合动态对象的凸分解；复用现有三维物理与镜头，不另建物理解算器。
