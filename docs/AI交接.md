## 4. 启动、查看代码和运行验证

在解压后的本工程目录操作，无需复现原电脑的绝对目录名。普通电脑选非系统盘；用户指定的远程4080 SUPER电脑选非C/D盘目录。

```powershell
.\workbench.cmd
.\preview.cmd -Scene 3d
.\preview.cmd -Scene perspective
.\editor.cmd
```

`editor.cmd`启动原生Godot编辑器，F5运行工作台。可在GDScript行号设置断点，查看调用栈和局部变量，用“远程”场景树检查实际节点。工作台默认OpenGL Compatibility；视频生产可选OpenGL或Forward+ Vulkan。本工程没有DX11切换。

完整运行包应带工程内Godot、FFmpeg和独立Python及所需Pillow；具体版本、下载校验和许可看本次依赖清单。源码包若缺`.runtime/`，按 `tools/setup.ps1` 说明恢复。不要依赖旧兄弟工程venv。重建脚本和迁移验收记录才是本轮依赖修复是否完成的依据。

所有Godot命令先加载 `tools/common.ps1`，以便将TEMP、APPDATA等重定向到工程盘。如下是定向分裂验证；日志和本次报告都应检查：

```powershell
. .\tools\common.ps1
& $Godot --headless --path $LabRoot --fixed-fps 120 `
  --script res://tools/validate_split_inheritance.gd --quit-after 12000
```

完整验收：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/validate_workbench.ps1 -Legacy -WavJob
```

在独立工程副本运行完整验收。Host检查会启动工作台并写默认文件桥，不能与用户正在操作的实例共享目录；真实生产部分会启动GPU渲染窗口。Godot可能退出0但日志含脚本错误；需同时检查日志和新生成的 `passed:true`，不能复用旧报告冒充本次通过。真实异步生产检查不要同时使用固定帧率和最大帧率。

## 5. AI控制与视频工作流

程序不依赖特定AI供应商。能读取/写入本地文件、执行工具和修改GDScript的AI即可开发。无需把用户账号、浏览器Cookie或模型密钥写进包。

工作台每约0.2秒发布 `outputs/control/scene.current.json` 和 `state.json`。先读最新 `revision` 和真实物体ID；将唯一命令写入 `inbox/<唯一名字>.tmp`，关闭文件后改名为`.json`；依次读取同名 `results/` 回执及新版本，再发下一条有依赖的命令。

例如修改标题，`base_revision`必须替换为刚读到的值：

```json
{
  "command_id": "handoff_title_unique_001",
  "base_revision": 17,
  "op": "scene.patch",
  "args": {"changes": {"presentation.captions.0.text": "绿色球能填满吗"}}
}
```

不要复用示例命令ID。`results/`已有同名回执时不会重复执行；版本冲突应重新读取并决定操作。所有有效命令、字段路径和回执见[使用说明第8节](工作台使用说明.md#8-ai命令文件协议)，没有通用`component.*`API。

制作流程是：布置和应用初始数据 → 运行检查 → 从初始场景录制 → 停止并保存Take → 寻帧检查 → 修改纯表现 → 生产。初始场景保存不等于保存下落瞬间，撤销不等于倒转物理。物理、机制、顿帧变更会使Take过期；文字、材质、灯光、声音和纯视觉特效通常可复用Take。

生产只读取Take，不重新求解；必须等任务 `complete` 且 `validation.json` 为 `passed:true`。任务名不能重用，同一工作台只容纳一个活动生产任务。输出规格为30/60fps、720×1280或1080×1920，1～3600帧且不能超过Take。

## 7. 已知限制与下一步

- Take目前整份JSON保存，最多60秒、60000采样、256动态＋256固定/区域；累计退役定义不占活跃预算，但仍增加文件体积。寻帧取不晚于目标的最近样本，无物理插值，也不能从回放姿态无缝接着求解。
- 接触位置是标明来源的几何估算；真实法线/冲量为null。最低冲击要求目前会拒绝 `impact_metric_unavailable`，没有已有效的真实强度阈值。
- `world.seed`尚未驱动物理随机；现有特效使用记录事件种子。同一Take可恢复，不能承诺同种子重算或跨机器逐位一致。
- 3D粒子仍是屏幕效果；目前没有真实碎片。默认同尺寸分裂、额外喷射速度是玩法，可增加面积/体积或运动能量，不伪称守恒。
- 字体从系统读取，未随包附带同一中文字体。没有缺字不代表跨电脑排版像素一致；要统一成片须选可分发字体并记录许可。
- 旧生产任务的冻结WAV路径曾保存为绝对路径；迁移旧任务不能只移动目录后直接声称可重渲染。优先用可移植场景/Take建立新任务，必要时明确重定位资产并验证。
- 中文路径、空格、Windows文件替换竞争、任务取消和错误日志都已有踩坑记录；不要吞异常或将空状态读成成功。

建议下一位AI先完成当前用户明确指定的任务。若用户继续前一轮破坏方向，按以下顺序提出可审查的小增量，不把全部设计一次实现：

1. 从参考三条原片确认“一击、耐久、破坏区域”规则，建立矩形/盒体预切分的小夹具。先实现计次和归零一次提交，再接真实碎块及同色视觉碎屑。
2. 将裂纹、破裂声音、进度文字、顿帧绑定同一事件，写入Take；验证持续接触不重复扣数、容量不足不丢原物体、回放和导出一致。
