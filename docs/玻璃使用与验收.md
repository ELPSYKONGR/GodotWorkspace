# 二维玻璃、计次破碎与实例化（2026-11-14）

## 使用

双击任务根“玻璃演示.cmd”，或者工作台顶部“玻璃演示”，点击“运行”。初始为一颗真实球、8块彩色环形玻璃（1～8次耐久）。物体页可选择玻璃修改破裂次数、数字字号、视觉碎屑数量和颜色；修改物理/耐久参数后点击“应用物体参数并重置”。“添加玻璃（2D）”创建矩形玻璃，可拖动、复制、删除或撤销。

已有活动工作台时启动器不会再开一个共享控制目录的实例。旧进程不会自动热更新源码，请先保存需要保留的场景/Take，再关闭旧窗口重新启动。

## 已实现

- 2D彩色半透明玻璃、亮边、斜向反光，星点背景；矩形和环形扇区均有对应原生静态碰撞体，扇区由小凸四边形组合。
- 只有带ball标签的动态物体原生接触才扣耐久；相同接触片段不重复计次，传感器重叠不造成玻璃损伤。碰撞锚点仍为几何估计，不声称取得真实冲量或法线。
- 剩余碰撞次数绑定真实损伤事件。玻璃面内数字有白字、黑描边、轻微缩放/亮度反馈；中心显示当前目标剩余值和HITS LEFT。完成后显示CLEAR。
- 碰撞位置生成确定性分叉裂纹，附着原玻璃而不是全屏叠图；归零仅移除一次完整玻璃碰撞体。暂停时延迟退役保持冻结，继续运行后提交。
- 飞散的是带透明填充和高光边的三角视觉碎屑，具有旋转、飞散、重力轨迹和2.4秒寿命。它们明确不参与物理碰撞，不冒充真实形状切割或刚体碎片。
- 裂纹、耐久、破裂生命周期写入Take；回放/寻帧/独立视频生产共用表现代码，倒退后再前进能还原同一碎屑位置和数字。

## 实例化范围

二维所有圆形物体通过一个MultiMeshInstance2D批量显示，原生刚体仍各自负责真实碰撞；圆环、闪光、普通粒子继续使用原来的批量路径。玻璃飞散碎屑共享一个三角网格和材质并实例化绘制。玻璃表面共享材质、白纹理和数字字体缓存；裂纹按损伤更新并批量绘线，避免每帧重建。

三维球体仍为原来的MeshInstance3D，本次没有把三维物体改成MultiMeshInstance3D，也没有提高256动态刚体上限。

## 验证

15阶段统一回归通过，包含Glass专项、原有分裂/容量/会话/界面/音频/回放、真实生产和WAV冻结生产。最新玻璃专项覆盖原生接触对应关系、逐次扣数、一次破裂、传感器排除、暂停/继续、回退恢复、碎片寻帧确定性、UI编辑撤销及不合法Take拒绝。

18秒原生录制曾产生19次损伤和3次破裂；最终样片为12秒、720×1280、60fps、H.264/AAC，完整媒体验证通过。样片声音使用已有bell合成音，并非真实玻璃录音。

本机真实窗口实测：玻璃场景18秒平均60.00FPS、P95 17.00ms、最长29.16ms；原百球场景25秒平均59.95FPS、P95 19.05ms、最长32.24ms，两轮均无超过33.34ms帧。当前测量仍有帧间隔波动，不是每帧严格16.67ms的硬实时保证。

## 范围与边界

这是参考视频7706016277194605307的玻璃观感和碰撞反馈复刻，不是原视频完整脚本逐帧重制。当前扇区角度固定；没有实现破裂后其它扇区自动扩张、2048关卡加速、真实3D折射或每块碎屑的物理解算。外围包含不可见安全边界，保持演示球在画面内。

配置字段：对象glass.hits（1～100000整数）、glass.shards（1～256视觉碎屑）、glass.font_size（8～96）；环形shape为arc，包含inner_radius、outer_radius、start_degrees、end_degrees，目前只支持静态2D。玻璃与普通圆球的数量没有混淆；视觉碎片不占真实动态刚体预算。仍不能保证任意未来场景每帧严格16.67ms。
