# 碰撞后停顿、渲染仍60帧的排查（2026-11-14）

## 已确认的原因

用户当前场景开启了split_hitstop，设置每次分裂暂停0.06秒。这个效果保持渲染和成片时间推进，但主动暂停物理和模拟时间；因此顶部FPS仍可为60，球体却会停止运动。120Hz下0.06秒向上取整为8个物理步，实际约66.7毫秒。分裂越来越密集时，暂停也更频繁。

这次直接复制当前初始场景，在独立工程副本做12秒真实GPU窗口对照，并记录接触、分裂、模拟时间和成片时间；没有使用fixed-fps当作性能证据。

| 指标 | 顿帧开启 | 仅关闭顿帧 |
|---|---:|---:|
| 渲染平均FPS | 60.12 | 60.11 |
| 最长渲染帧 | 29.23ms | 29.22ms |
| 累计物理顿帧 | 2.07秒 | 0秒 |
| 检出的25ms以上模拟冻结片段 | 31 | 0 |

开启时的冻结片段约50～67毫秒，和分裂事件同步；关闭后同场景的这些冻结消失。此次可复现停顿主要来自主动顿帧，单看渲染平均FPS无法识别。

## 修复与使用

- 二维、正交三维和透视三维分裂预设默认关闭顿帧；机制页新建规则的缺省值也关闭。需要强调打击感时仍可手动勾选“启用分裂顿帧”。
- 机制页明确解释该开关会暂停运动。顶部将FPS标为“渲染FPS”，启用时显示“物理暂停”和累计顿帧秒数，继续使用引擎实测FPS。
- 当前初始场景另存为scenes/流畅分裂_20261114_150910.json，仅将顿帧规则设为false；原场景备份于outputs/motion_stutter/scene_before.json，未覆盖已有用户配置。修复版本已在主工作台打开。
- 已保存的旧场景保留自己的开关值；需要连续运动时取消该开关并应用。旧Take已记录的停顿不会被修改设置抹除，需要重新录制。

本轮没有改变反弹、分裂数量、子球速度、碰撞求解频率或容量限制，也没有关闭分裂机制。之前回放路径的性能优化继续保留。当前对照没有出现大于33.34ms的渲染帧，但不将此作为任意场景每帧严格16.67ms的保证。

## 验证与证据

20阶段完整回归64.258秒通过。新增6项专项覆盖连续分裂后的模拟推进、三个预设的默认值、关闭时零顿帧、手动启用仍能暂停并录入Take，以及渲染FPS与物理暂停的状态区分。原有Session验收显式开启可选顿帧，继续验证两种时钟。
