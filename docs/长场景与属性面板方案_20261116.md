## 2. 长场景如何设计

### 推荐起点：有限长世界 + 固定画幅 + 跟随镜头

示例采用 **720×20,000 的二维世界**，镜头看到其中 **720×1280** 的区域；成片可仍为 **1080×1920、60 fps**。20,000 是方案示例，尚未做该长度的工程验收。

小球真实位置从 Y=420 落到 Y=5,000，镜头向下移动，而小球依旧位于世界 Y=5,000；不把小球传送回顶部，也不移动整套碰撞障碍。成片总像素数始终由输出分辨率决定。

```text
长世界                    镜头/视频画幅
Y=0     ┌──────────┐
        │  起点    │
        │          │
Y=3200  ├──────────┤ ← 当前镜头顶部
        │    ●     │   只拍摄这一段 720×1280
Y=4480  ├──────────┤
        │  后续障碍│
        │    ↓     │   世界继续向下延伸
Y=20000 └───地面───┘
```

实现顺序：

1. 编辑器独立保存可布置范围；侧墙、斜坡和最底部地面仍为明确的真实物体。调整“世界高度并同步边界”通过一个命令事务更新物体，不建立两份互相覆盖的碰撞几何。
2. 画幅仍使用固定大小 SubViewport，新增二维 CameraRig/Camera2D。不要申请 720×20,000 的视频纹理，也不要单纯放大 `world.logical_size` 就宣称镜头跟随完成。
3. 跟随采用 Y 轴、画面高度42%的构图位置、32%～58%死区、0.18秒平滑，可选“只向下”。这些是可调起点，需要用实际运动调优。
4. 镜头限制限制的是**取景范围**；物理墙和地面决定碰撞边界。开放底部时，移除地面并允许镜头继续向下；编辑范围不是隐形地板。
5. 离开镜头的物体默认继续物理解算。不按可见性直接休眠、删除或清空碰撞；视锥外只可省略绘制。数量、接触密度、录制时长影响成本，场景长度本身不是性能保证。
6. 编辑用缩略图/平移/缩放独立于成片镜头，既能查看长世界，也能切回“镜头视图”检查构图。

### 小球分裂后跟谁

- 指定目标时，保留根球谱系 ID；原球退役后沿后代寻找存活目标。
- 默认向下路线可选“最低存活后代”；同深度以稳定 ID 排序，并用切换滞后避免多个球之间快速跳镜头。
- 多球全貌用“后代群组中心/包围盒”，配最小/最大缩放和边距；不要无限缩小到观众看不清球。
- 目标全部消失时默认保持最后镜头，并给出原因；可再选择转到指定终点。规则必须显式配置，不能静默改跟随目标。

### 容易遗漏但必须一起改的地方

| 路径 | 要求 |
|---|---|
| 物体绘制、荧光批次、玻璃 | 使用世界到镜头的统一变换；批量绘制包围盒不能仍只覆盖首屏 |
| 点击/拖动物体 | 用镜头变换的逆变换返回世界坐标，包含缩放、预览黑边及输出比例 |
| 粒子/光圈/拖尾 | 保存世界锚点后投影，镜头移动时不能与真实碰撞位置分离 |
| 标题、字幕、安全区 | 默认在屏幕空间固定；物体耐久数字等世界标注随世界移动 |
| Take 回放、seek、生产 | 从相同轨迹生成镜头轨道；不能靠 seek 前的平滑器历史决定当前镜头 |

建议把镜头轨道作为可重建的**表现缓存**：按固定时间采样，从 Take 起点计算平滑/目标切换后保存。修改镜头只重新烘焙镜头缓存，不重求物理。录制中分裂顿帧默认同时保持跟随镜头；背景音乐按成片时间继续。

实时跟随和镜头烘焙共用固定步长的跟随计算；回放时关闭相机的额外状态平滑，直接应用镜头轨道，避免双重平滑和顺播/seek结果不同。

当前 Take 有60秒、60,000采样和活跃物体限制，生产最多3600帧；“长空间”不等于“已支持无限时长视频”。超长录制、分块 Take 和分段生产另做扩展。超大坐标也会遇到浮点精度问题；短视频先不引入无限世界和原点漂移。

2.5D/3D 后续用 Camera3D 父级 Rig 沿目标移动，取景方向与重力方向解耦；三维单位为米，不能照抄二维20,000像素参数。当前2.5D仍是三维物理+正交相机。

## 3. 属性界面如何缩短、怎样分组

推荐桌面布局：左侧180～220 px对象树，中间弹性预览，右侧360～420 px可拖动检查器。小窗口可收起对象树；较窄时检查器改为单列抽屉。

- 常规数字框88 px，长整数/科学计数可扩至112 px；单位单独显示。数字框不设置横向扩张，只让行内空白区伸缩。
- 文本、文件路径和长下拉框可以填满余宽；不能为缩短数字框连带截断它们。
- 位置 X/Y、尺寸 W/H成组；三维 X/Y/Z可在标签下一行排列，空间不足自动折行。不同维度显示 px、px/s 或 m、m/s。
- 名称、变换、视觉材质、物理材质、机制分别分组；高级碰撞位掩码收起。预设先选，少量常用参数常驻。
- 保留 PendingEdits 跨页草稿、统一校验、应用并运行和撤销/重做。视觉修改可即时预览；物理修改显示“需要重新录制”，避免运行中悄悄改求解状态。
- 多选时仅展示共同属性，混合值明确标记；共享材质修改前显示受影响物体数量，默认“复制为独立材质”避免误改其它物体。

## 4. 视觉材质和物理材质分开

| 类别 | 数据示例 | 对真实运动的影响 |
|---|---|---|
| 视觉材质 | 颜色、贴图、透明度、描边、发光；3D粗糙度/金属度 | 不改变碰撞，可复用 Take |
| 物理材质 | 摩擦、弹性，以及需要显式选择的组合规则 | 会改变运动，旧 Take 过期 |
| 声学配置 | rubber/metal/wood/glass 等声音身份、声音路由 | 只改变声音，不能反过来给物体施力 |

“金属外观”不自动等于“高弹性”或“金属音”。可提供联动预设，但应用时明确展示究竟修改了哪些字段。

视觉库使用 `presentation.materials`；对象使用 `appearance.material_ref` 加可选覆盖。Godot Resource 只作运行时缓存，JSON是持久化权威来源。共享材质与独立副本都通过 CommandService 校验并提交。

2D采用 CanvasItem/现有批次着色器参数；3D采用 StandardMaterial3D。二维平涂没有真实的PBR粗糙度，界面应禁用并解释这类字段。透明、折射和玻璃须按后端能力单独标识，不能用透明度开关宣称已完成真实玻璃渲染。

子球默认继承视觉材质，基础色再应用既定的同色系逐代变浅；高代数设置亮度上限，避免最终全白看不见。颜色策略不应改动球的几何、质量或反弹参数。

## 5. 背景、碰撞声音、音乐如何配置

### 背景

第一阶段支持纯色、双颜色渐变、图片；图片可等比覆盖/包含/平铺。默认绑定屏幕，镜头下移不露空白。世界贴图需有世界位置和尺寸；视差、视频背景、HDRI列为后续选项，不能暗示已经具备。

背景图属于表现资源，使用工程内相对路径；导入时复制到 `assets/backgrounds/`。屏幕背景在 Camera2D 变换外绘制；世界背景处于同一世界变换中。背景、世界、屏幕文字的层级要固定。

### 碰撞音：匹配一对对象，而非分别给两球重复发声

| 规则示例 | 默认音色示意 | 可以独立调整 |
|---|---|---|
| ball × ball | 木质短音 | 音频资源、音量、音高、强弱映射 |
| ball × wall / floor | 金属轻击 | 同上，与球球互不影响 |
| ball × glass | 清脆铃音 | 同上；破裂音可用单独事件 |
| split.committed | 单独分裂音 | 替代同刻接触音，或显式选择叠加 |
| 未命中规则 | 默认点击音/静音 | 全局兜底 |

这些音色是初始审美方案，可任意替换，不代表材质必须如此发声。

匹配顺序：明确对象对 > 声学配置对 > 标签对 > 全局兜底；同级规则按优先级、稳定顺序只取一条。A碰B与B碰A是同一个对，使用已存在的 contact_episode_id 去重；只消费 enter，不因帧数高而重复播放。

声音身份可放在 `presentation.audio.object_profiles`，后代按谱系继承；不塞进物理材质造成无意义的物理轨迹失效。原先没有这些配置的旧场景迁移成一条全局兜底，听觉保持兼容。

同一物体对短间隔限流与全局最大声部分开；不同对象的同时碰撞可同时发声。限流只丢弃可听声部，不删除物理事件。当前只有相对线速度估计，不能标为真实法向冲量/撞击能量；新面板必须显示估计依据。

### Music、Ambience、SFX 三条独立路径

- 背景音乐：资源、音量、入点、循环、淡入/淡出、静音/独奏。
- 环境声：另一份资源和音量，可循环，独立开关。
- 碰撞音：事件驱动，在需要时触发“音乐让位”。让位幅度、启动和恢复包络须与离线混音一致。
- Music/Ambience按成片时间播放，分裂顿帧时继续；seek默认静音并停止旧声部，恢复播放时从正确采样位置开始。
- 统一导入将 MP3/OGG/WAV 经现有 FFmpeg 规范化为48kHz PCM工作资源；这是拟新增导入能力。**当前自定义碰撞音仅接受整数PCM WAV**，并未已经支持任意音频。

不能仅给预览加两个 AudioStreamPlayer 就结束：需要共用 AudioPlan（事件时间、路由结果、资源、增益/音高、限声部、淡变），预览和 Python 离线混音消费同一计划。采样位置采用 `round(presentation_time * 48000)`；音高变化使用独立、可复算的事件随机源，不能扰动物理。

生产提交时冻结所有引用资源及摘要：材质/贴图、背景图、碰撞音库、音乐和环境声、镜头计划。任务运行后修改源素材不能改变已排队的视频。最终检查削波、开头/结尾、循环接缝、音轨长度与画面事件对齐。

编辑范围保存在 metadata，仅用于布置；实体边界仍由 objects 的形状/位置定义。高度同步修改墙和地面时，这些物体变化进入 simulation_hash。镜头、纯背景、外观材质与声音留在表现依赖中；只失效相应镜头/帧/音频缓存。

| 模块 | 复用/新增职责 |
|---|---|
| SceneDocument / CommandService | 新字段校验、旧数据迁移、批量边界更新、修订与撤销；继续供 UI/AI 共用 |
| World2D / World3D | 真实刚体、物理材质和接触；补齐静态材质，不因镜头移动改物理坐标 |
| ContactRules | 分裂/破坏机制及生命周期；不负责选择音乐和绘制背景 |
| Stage / CameraRig | 世界投影、逆变换、屏幕背景/文字、镜头轨道；提供统一投影接口 |
| 材质解析 | 根据材质ID缓存运行时资源，服务2D/3D表现；单对象覆盖不污染共享材质 |
| 音频计划与适配器 | 路由/去重/时间表共用；Godot实时播放与Python混音各自适配 |
| Production | 冻结全部输入；继续使用Take逐帧渲染，不重复求解物理 |

本工程目前 World 仍混合物理和部分绘制，ContactRules仍访问World。此方案沿既有命令/数据流程逐步收敛，不能把文档中的模块图当成严格四层解耦已经完成。

## 7. 建议落地顺序与验收

| 批次 | 工作内容 | 验收目标 |
|---|---|---|
| A 紧凑UI及材质应用补缺 | 表单宽度/向量布局，模式相关字段，静态物理材质 | 窄窗口不遮挡，数值未编辑不变；动态/静态材质各有对照；草稿/撤销保留 |
| B 长世界与镜头 | 有限长世界模板、缩略图、跟随/后代策略、统一投影 | 球越过首屏继续模拟；拖动坐标正确；分裂后不丢跟随；事件特效与物体贴合 |
| C 材质与背景 | 逐物体视觉材质、独立副本/共享、背景三类与锚定 | 只改外观不使物理Take过期；共享影响范围明确；2D/2.5D/3D各验证适用字段 |
| D 多轨声音与完整生产 | 音效对路由、BGM/环境声、导入、AudioPlan、资产冻结 | 球球/球墙独立可辨；预览/成片按同规则；seek/循环/顿帧/尾音正确 |

关键跨模块验收：在同一 Take 的多个时刻顺播/前后seek再导出，镜头、世界标注和粒子位置一致；录制和导出全程使用固定画幅；音画触发误差目标≤一输出帧，同时核对采样点。真实运行检查在独立副本，避免覆盖用户的 outputs/control。

无需引入新的通用编辑器或另建物理引擎。新增库之前优先使用原生能力，下列 GitHub 源码于本轮通过公开 API 核对了相关字段：

- [Godot Camera2D](https://github.com/godotengine/godot/blob/master/doc/classes/Camera2D.xml)：限位、拖动死区、位置平滑。
- [Godot Camera3D](https://github.com/godotengine/godot/blob/master/doc/classes/Camera3D.xml)：正交/透视与范围。
- [Godot BaseMaterial3D](https://github.com/godotengine/godot/blob/master/doc/classes/BaseMaterial3D.xml)：颜色、粗糙度、金属度、发光。
- [Godot CanvasLayer](https://github.com/godotengine/godot/blob/master/doc/classes/CanvasLayer.xml)：屏幕层与跟随视口。
- [Godot AudioStreamPlayer](https://github.com/godotengine/godot/blob/master/doc/classes/AudioStreamPlayer.xml)：资源播放、音量、总线路由；多轨时序及离线一致性仍需本工程实现。

这些参考证明原生组件可复用，不能证明本工程已接入，亦不构成本机长场景性能实测。
