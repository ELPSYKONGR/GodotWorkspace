# 解压视频工作台使用说明

日期：2026-11-13。本文描述当前已实现的首版，以工程里的`config/workbench_*.json`、`src/`和实际生产产物为依据。完整目标方案另见[工作台扩展方案](工作台扩展方案.md)，不要把其中的后续设计当作现有按钮或API。

## 1. 启动与工作流

新功能：顶部“应用更改并运行”一次应用所有已修改的场景设置（包括多个物体和输出参数），校验后从初始布局重新运行；失败不提交，一次撤销可恢复整批。机制页“分裂最低碰撞速度（0关闭）”可排除低速接触，二维用px/s、三维用m/s，采样接触前一物理步的相对线速度。详见[使用与验收](性能与批量应用验收.md)。

工程目录：`D:\codex\AGI\AI视频三项目评估_20261111\06_本地部署\godot-video-lab`。

双击`preview.cmd`或`workbench.cmd`进入工作台。双击`editor.cmd`打开Godot编辑器，在编辑器按F5同样运行工作台。也可在工程目录运行：

```powershell
.\preview.cmd -Scene 2d
.\preview.cmd -Scene 3d
.\preview.cmd -Scene perspective
```

顶部“新建场景”统一选择二维、正交三维、透视三维和玻璃演示。默认包含示例物体；取消勾选则创建该类型的空场景，保留相机、重力和表现设置。四种类型共用后续编辑、运行、录制与生产流程。日常流程：

现增加第五个选项“荧光演示”，带128颗真实碰撞球和青蓝/粉色边框。普通二维场景也可在“渲染”页勾选“启用二维荧光材质”，调整光晕范围/强度、小球高光大小/强度后点击“应用二维荧光材质”。颜色沿用物体页颜色；这些是表现设置，不重置物理，也不使已有Take过期。详见[二维荧光使用与验收](二维荧光使用与验收.md)。

1. “编辑布置”返回初始布局，添加、点选或拖动物体，修改参数后点击该页“应用”。
2. “运行／暂停”是同一个按钮：点击运行后显示“暂停”，再点击暂停后恢复“运行”，模拟和轨迹回放均适用。录制中点击暂停沿用原行为，停止本次录制并保留轨迹。“单物理步”只推进一次求解。“重置”返回保存于当前文档的初始布局。
3. 点击“录制”，它从当前初始场景重新开始记录。运行所需时长后点击“停止录制”，得到Take。
4. 拖动底部时间轴检查实际运动；录制停止后的轨迹可以往返查看，点击“运行”播放回放。
5. 调整文字、颜色、材质、相机、声音和屏幕特效，不必重复录制相同物理。
6. “生产”页提交新的任务名，等待`complete`与验证通过后查看成片。

“保存场景”只保存初始场景数据，不会把下落中的瞬间位置覆盖到初始布局。“撤销／重做”针对初始数据编辑，不是倒转物理历史；编辑历史最多50条。当前没有聊天输入框，AI通过本地命令文件控制同一工作台。

### 场景文件

- “新建场景”：从四种类型创建独立副本，不覆盖内置示例；新场景标记为未保存。
- “打开场景”：选择已有JSON，校验通过才替换当前场景；损坏文件不会清空当前编辑。
- “保存场景”：已有文件保存到原路径；新场景弹出文件选择窗口。默认目录为工程下`scenes/`，支持中文文件名，也可选其它目录。
- “另存为”：保存到新文件，并将其设为当前文件；覆盖已有文件由文件窗口提示确认。内置`config/workbench_*.json`四个示例受保护。
- 顶部显示当前文件、类型、完整路径和未保存星号。已应用的编辑使星号出现；保存或撤销到已保存内容后消失。未点击“应用”的属性输入不属于场景数据。
- 新建或打开时，若当前场景有未保存修改，会提示“保存并继续／不保存并继续／取消”。取消文件窗口或保存失败均不会继续切换。

场景JSON保留物体、机制、相机、声音、特效及生产设置；运动过程仍使用Take单独保存。`scenes/`属于用户数据，默认不纳入源码Git提交。专项验证见[场景管理验收](场景管理验收.md)。

## 2. 三种画面模式

| 模式 | 物理与画面 | 坐标/用途 |
|---|---|---|
| 二维 | 原生`RigidBody2D`，圆和矩形 | 720×1280逻辑画面；X向右、Y向下，位置为逻辑px、速度px/s |
| 正交三维，即当前2.5D | 原生`RigidBody3D`，球/长方体，正交相机 | 真正三维运动，远近不产生透视缩放；Y向上，单位m、m/s |
| 透视三维 | 同一三维刚体世界，透视相机 | 有近大远小；FOV与相机位置/目标可调 |

2.5D不是把二维碰撞贴上一个假三维外观。二维与三维的世界单位不同，不要把二维450的重力直接照搬到三维。提高视频分辨率只提高输出像素，不会把物体、速度或重力放大。

预览使用独立720×1280逻辑视口，保持宽高比。工作台变大/变小时会留黑边，选取坐标会先去除黑边。二维编辑模式可直接拖动；三维拖动位于选中物体当前高度的XZ平面，Y高度、旋转和尺寸用数值修改。锁定物体不能拖动。

底部“◀一帧／一帧▶”是成片时间寻帧，默认30fps，提交生产后使用该次任务FPS。顶部“单物理步”推进一个物理解算步，两者含义不同。

特效开关：拖影、撞击光圈、撞击闪光、碰撞粒子、分裂粒子、分裂闪光分别控制，点击立即应用。“特效总开关”临时隐藏全部效果，重新开启后保留分项选择；点击“保存场景”写入文件。数量、寿命、速度和时间域仍点击“应用粒子与拖尾”。碰撞粒子与闪光默认关闭以兼容旧场景，分裂粒子缺省开启。密集接触按物体对合并，并最多同时显示16组碰撞喷溅/闪光，完整物理事件和录制记录不受影响。荧光材质自身的光晕在“渲染”页控制，独立于这里的运动特效。

文字位置、逐代颜色参数、移除规则和更细的场景字段也可通过JSON/AI补丁修改；并非所有可用字段都有专用面板。当前没有框选、完整三维移动/旋转手柄、网格吸附、分组编辑或可自由停靠的界面。

## 4. 接触、分裂与物理边界

碰撞来源是Godot引擎的接触通知。原生物理负责反弹、摩擦和运动；分裂属于接触后明确执行的玩法动作。当前实现`split_on_contact`、`despawn_on_contact`和`hit_stop_on_event`，其中接触移除通过场景JSON/AI配置。

分裂移除父球，并创建指定**总数**的子球；默认1→2，不保留原球。新生保护默认0.08秒。保护到期时若还在同一轮接触中，重新检查；已经离开的旧接触不补发。球球双方在同一批次评估，墙角多个来源不会使同一父球重复提交分裂。

容量或出生空间不足时整次跳过并记录原因，不把1→2偷偷改成1→1。配置的动态上限同时约束分裂。分裂后的子球沿同色系逐代变浅；这由`appearance.generation_color`控制。保持尺寸的分裂是人为玩法，并不宣称质量/能量守恒。

“机制→子球继续分裂”默认开启，旧场景缺少该字段也按开启处理。关闭后，仅初始球（`generation=0`）可分裂，产生的子球仍运动、碰撞，但不执行该分裂规则；子球的其他机制不被删除。开启后，每一代都可在满足规则时继续分裂。对应字段为`split_on_contact`规则的`params.children_can_split`，需要布尔值`true`或`false`；修改后点击“应用机制并重新模拟”。

此开关不取消物体数量上限。顶部显示动态物体“当前数/上限”，达到上限时明确显示“已达上限”。例如默认两颗初始球、每次1→2、上限48，累计46次成功分裂后达到48颗，之后的分裂会被拒绝。已有8秒二维Take实际记录了第8代子球，以及容量不足、新生保护和出生空间不足三类拒绝；并不是只支持第一代。

调试页会将最近一次机制未执行的原因翻译为中文，并保留原始事件：

| 原因 | 含义与处理 |
|---|---|
| `children_split_disabled` | 该规则关闭了子球继续分裂；在机制页开启并重新模拟 |
| `capacity_limit` | 完整生成这批子球将超过上限；可在2～256之间调整最大动态数 |
| `birth_space_blocked` | 找不到整批子球的非重叠出生位置；扩大容器、减小半径或减少初始密度 |
| `newborn_guard` | 出生后短暂保护尚未结束；默认0.08秒，持续接触在保护结束后重查 |
| `minimum_radius` | 缩小分裂时子球将低于物理最小尺寸 |
| `tag_mismatch` | 碰撞对象标签未匹配所选触发对象 |

“最近一次”是历史记录，保护或空间限制可能随后已解除。增加最大动态数也不能解决空间不足；保持原尺寸会更快拥挤。JSON中的`params.size_policy`可选`conserve_area`（二维）或`conserve_volume`（三维）让子球逐代变小，但最终仍受最小尺寸和容量限制。

`dynamic`受力运动，`static`作为实体边界，`sensor`只感知接触。碰撞层与掩码是位掩码，例如1、2、3，不是简单的第几个图层。标签还需满足规则过滤；看起来碰到了、但标签不匹配时不会执行该规则。CCD用于降低高速穿透风险，不能替代合理尺寸/速度/物理频率。

调试中的接触锚点由形状几何估算，字段会标明来源；真实接触法线与冲量不可用时为`null`。不能用这个锚点声称实现了精确引擎接触点、法线或冲量调试。

## 5. Take、顿帧与修改后的处理

Take是实际轨迹文件，保存初始场景、物体定义、生命周期/父子关系、姿态样本、事件和时间。回放与生产停用物理解算，直接恢复记录；回放不会再次触发分裂，也不支持从回放姿态无缝接着求解。

当前Take是**完整JSON**，并非分块流式存储。限制为60秒、60000个采样、512个活动物体，其中动态最多256、固定/传感最多256。它是防止无限增长的边界，不表示最大组合下内存/磁盘都很小；密集场景先录制短片。超过录制边界会报错，不会把截断轨迹当作完整成功文件。

寻帧采用二分查找，取不晚于目标时间的最近已提交样本，不做碰撞之间的物理插值。相同Take可导出不同FPS；这不代表不同显卡像素完全一致，也不意味着从同一种子重新模拟能跨机器完全一致。

两种时间分别显示在底部：

- 模拟时间：实际物理解算推进；顿帧时停止。
- 成片时间：最终视频时间；顿帧时继续，播放碰撞声音或指定时间域的表现。

手动暂停同时停住这两种时间，面板、AI命令轮询和生产任务仍可使用。特效的`simulation`时间域随物体一起冻结，`presentation`时间域在顿帧期间继续变化。

| 修改内容 | 是否重录 |
|---|---|
| 初始位置/速度、尺寸/形状、质量、重力、摩擦/弹性、碰撞过滤、分裂/移除规则、顿帧 | 需要；旧Take标记过期，生产会拒绝 |
| 文字/字体/字号、颜色、材质、灯光、相机、声音、纯视觉特效 | 可复用已有Take，重新渲染/混音 |

加载Take时如果当前物理场景不同，会恢复该Take匹配的初始场景并标记为未保存副本，避免覆盖之前的场景文件。停止录制默认写`outputs/takes/latest.json`，同时保存`take_<唯一值>.json`归档。新v2场景文件没有自动监听；手改JSON后点击“打开场景”或发送`scene.load`。

## 6. 声音与本地WAV

合成音色为木质短音`wood`、钟声`bell`、点击`click`。实时预览与离线混音使用相同音色/参数规则；声音限流只影响听觉，不会删除物理碰撞或改变机制。

本地文件支持整数PCM WAV：8/16/24/32位、单声道或立体声、8～192kHz采样率。浮点WAV、压缩WAV、MP3等不能直接作为当前碰撞资产。`wav_path`留空使用合成音；非空但无法读取/不支持时，“调试→声音状态”显示错误。

工作音轨是48kHz立体声PCM WAV，最终视频为AAC。声音按事件的成片时间定位到采样点，不录电脑扬声器。音高、音量、最短间隔和声部上限在预览与离线生产中共同使用。拖动寻帧时静音并停止旧声部，避免反复倒放触发噪声。

任务入队时会把外部WAV复制到本任务`assets/collision.wav`，冻结快照改为引用这份文件。生产期间修改/删除源WAV不应影响该任务；以后新建任务仍需要其所配置的源文件。

## 7. 视频生产与后端

“生产”页选择：

| 参数 | 取值/含义 |
|---|---|
| 任务名称 | 仅字母、数字、下划线、短横线；不能与已有任务重名 |
| FPS | 30或60；不等于物理Hz |
| 帧数 | 1～3600；输出时长=帧数÷FPS，不能超过Take或其60秒边界 |
| 尺寸 | 720×1280或1080×1920竖屏 |
| 后端 | `gl_compatibility`为Compatibility / OpenGL；`forward_plus`为Forward+，本工程显式使用Vulkan |

两种后端都已经实际生成带声音视频：二维OpenGL样片720×1280/30fps/8秒；三维Forward+ Vulkan样片1080×1920/60fps/3秒，Vulkan日志实际设备为AMD RX 6650 XT。当前不是DX11渲染；有真实GPU渲染的独立Godot进程输出画面，不能用headless的空渲染器冒充视频生成。

生产冻结输入后独立运行。单个工作台最多一个活动任务；现版没有多任务调度器。取消会写本任务的取消请求，由生产进程停止本任务所启动的工作，保留日志和已有中间帧，预览继续运行。任务状态显示当前渲染、混音、编码或验证阶段；渲染结束不等于最终视频完成。

```text
outputs/jobs/<name>/
  job.json                 输出规格
  scene.snapshot.json      冻结初始数据和表现
  take.json                冻结实际轨迹
  assets/collision.wav     使用外部WAV时的冻结副本
  frames/frame_0000000.png  干净画面序列
  mix.wav                  离线工作音轨
  final.mp4                最终H.264/AAC视频
  status.json              实际任务阶段/结果
  validation.json          完整媒体检查
  *.log                    各阶段诊断
```

验证包含尺寸、帧率、实际帧数/时长、完整视频解码、黑帧、H.264/AAC、48kHz音轨、应有声音时的非静音、事件采样定位和编码后起音对齐等。`validation.json`中的`passed:true`才表示整组检查通过。音效关闭时允许静音，不能仅凭存在一条音轨判断声音正确。

实测产物：

- [二维8秒MP4](../outputs/samples/2d_physics.mp4)。
- [三维Vulkan 3秒MP4](../outputs/samples/3d_vulkan.mp4)。

对应原始任务及机器可读验证路径见[samples/manifest.json](../outputs/samples/manifest.json)。综合验收过程见[工作台验收报告](工作台验收报告.md)。

## 8. AI命令文件协议

工作台运行时，每约0.2秒发布：

| 路径 | 内容 |
|---|---|
| `outputs/control/scene.current.json` | 当前初始场景及`revision` |
| `outputs/control/state.json` | 模式、双时间、轨迹/任务状态、事件、声音与错误 |
| `outputs/control/inbox/<唯一文件名>.json` | AI提交的命令 |
| `outputs/control/results/<同文件名>.json` | 执行结果 |
| `outputs/control/processed/<同文件名>.json` | 已处理的输入归档 |

先读取最新`revision`与真实物体ID，再创建唯一`command_id`和文件名。先写`.tmp`，写完关闭文件后原子改名为`.json`，避免读到半份命令。按一条命令→读取回执/最新版本→下一条依次提交依赖操作；不能把所有编辑都写同一个旧版本号。

例：假设当前版本为12，修改标题和字号：

```json
{
  "command_id": "ai_title_001",
  "base_revision": 12,
  "op": "scene.patch",
  "args": {
    "changes": {
      "presentation.captions.0.text": "绿色球能填满吗",
      "presentation.captions.0.font_size": 42
    }
  }
}
```

字段路径用点号，数组用数字索引。初始物体移动示例；`ball_A`仅是二维默认预设的ID，其他场景必须读取实际ID：

```json
{
  "command_id": "ai_move_001",
  "base_revision": 13,
  "op": "object.update",
  "args": {
    "id": "ball_A",
    "changes": {"transform.position": [240, 420]}
  }
}
```

回执至少包含`ok`、`command_id`、`revision`；按操作增加`error`、`message`、`changed`、`requires_reset`、`path`。版本过期在修改前拒绝，AI应读取最新场景、使用新命令ID重新决定操作。运行进程内相同`command_id`不会再次执行；持久结果文件防止同名输入重复处理，因此不要复用旧文件名或删除回执来触发重做。

当前实际支持的命令：

| 命令 | 主要args |
|---|---|
| `scene.preset` | `name`: `2d` / `3d` / `perspective` |
| `scene.load` / `scene.save` | `path`：`res://`工程路径或绝对路径 |
| `scene.new` | `name`：`2d` / `3d` / `perspective` / `glass`；`blank`可选，true为空场景，缺省含示例；创建未保存副本 |
| `scene.validate` | 无 |
| `scene.patch` | `changes`：点号字段路径到值的映射 |
| `object.add` | `kind`: `ball` / `box` / `wall` |
| `object.select` / `object.remove` / `object.duplicate` | `id` |
| `object.update` | `id`和`changes`；也兼容`object_id` |
| `object.arrange` | `mode`: `row` / `grid`，只排列未锁定动态物体 |
| `history.undo` / `history.redo` | 无 |
| `simulation.play` / `pause` / `step` / `reset` / `edit` | 完整名称如`simulation.pause`；无args |
| `take.record` | 从初始场景开始录制 |
| `take.stop` / `take.save` / `take.load` | `path`，默认`res://outputs/takes/latest.json` |
| `take.seek` | `time`：成片秒数 |
| `audio.audition` | 试听已应用音色 |
| `render.enqueue` | `name`、`fps`、`frames`、`width`、`height`、`backend` |
| `render.cancel` / `render.open_output` | 无 |
| `preview.snapshot` | `path`，如`res://outputs/control/preview.png`，父目录需存在 |

没有通用`component.*`命令。机制列表通过`scene.patch`修改`mechanisms`，对象挂载规则通过`object.update`修改`mechanisms`；属性由同一校验器检查。AI命令与右侧面板走同一个服务，不直接给运行节点随意赋值。

## 9. 无界面录制与命令行生产

在工程目录运行，先加载便携路径环境。录制使用真实物理；生产外层可以无界面等待，但内层仍启动真正的Windows图形渲染进程。

```powershell
. .\tools\common.ps1

& $Godot --headless --path $LabRoot --fixed-fps 240 `
  --script res://tools/record_take.gd -- `
  --scene=res://config/workbench_2d.json `
  --output=res://outputs/takes/my_take.json --seconds=8

& $Godot --headless --path $LabRoot `
  --script res://tools/produce_take.gd -- `
  --scene=res://config/workbench_2d.json `
  --take=res://outputs/takes/my_take.json `
  --name=my_video_01 --fps=30 --frames=240 `
  --width=720 --height=1280 --backend=gl_compatibility
```

生产命令还可增加`--wav=E:/素材/碰撞.wav`；路径含空格时把整个参数用引号包住。使用新的任务名，避免覆盖旧输出。场景物理与Take不匹配会拒绝执行。`produce_take.gd`等待到完成、失败或取消才返回，不把“成功启动子进程”当作生产成功。

## 10. 查看代码、调试与扩展

主要业务逻辑为GDScript，Godot底层为C++。工作台界面使用原生`Control`，视频画面在独立`SubViewport`；生产另开干净Stage。当前没有另写DX11/Vulkan底层引擎，后端由Godot管理。

在Godot编辑器打开`src/ui/workbench.gd`或相应模块，点击行号设置断点，按F5运行。程序停住后可查看局部变量/调用栈；运行时切换“远程”场景树查看实际刚体、相机、界面节点。编辑器F6只运行当前场景，初学时优先用F5运行完整工作台。

数据与渲染分离方式：

```text
v2 JSON初始数据
  → CommandService校验/修订/编辑历史
  → SceneSession与World实际求解
  → Take记录实际姿态与事件
  → Stage以数据渲染文字/材质/声音/特效
  → 独立任务冻结输入，渲染/混音/编码
```

日常AI创作优先改JSON/命令：布局、初速度、标签、参数、相机与表现。新机制需要修改`src/mechanisms/contact_rules.gd`及参数校验；新物体需要在数据校验与二维/三维工厂支持形状；新表现优先在`presentation/`消费已有事件，不修改碰撞规则。文件明细和模块关系见[FILE_INDEX](../FILE_INDEX.md)。

现版没有软体、流体、布料、任意复杂网格、力场/马达、GPU粒子物理、分块Take、多轨剪辑或多任务调度。不要求修改Godot引擎源码即可扩展当前业务模块，但不能只加一个面板字段就声称新增了对应引擎能力。

## 11. 存储、依赖与排错

请通过`preview.cmd`、`workbench.cmd`、`editor.cmd`或先加载`tools/common.ps1`运行。它们将`APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP`指向工程`.runtime/`，Godot采用`_sc_`便携模式；输出和控制文件都留在本工程。直接启动引擎EXE可能绕过这套路径约束。

现阶段不需要NVIDIA显卡才能做已验证的二维/三维样片。若迁移到远程4080电脑，按既有要求将工程部署在其非C/D盘；本次实现保存在本机D盘。Python可用`VIDEO_LAB_PYTHON`指定，否则依次查找工程`.runtime/python/python.exe`及同级`relaxing-physics/.venv/Scripts/python.exe`。本机目前复用同级环境，移动单独Godot文件夹时须提供Python及依赖库。依赖来源见[依赖来源](依赖来源.md)。

需要重复验收时运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/validate_workbench.ps1 -Legacy -WavJob
```

它会运行世界、会话、命令、容量、UI、表现、混音、工作台主机，以及可选旧版基线和真实WAV生产。每阶段检查退出码、Godot日志及本次新报告；总结果在`outputs/workbench_suite.json`，分阶段报告及日志路径也记录在其中。

| 现象 | 检查 |
|---|---|
| 按“生产”提示先录制 | “运行”不会自动生成Take，需点击“录制”后停止保存 |
| Take过期 | 修改过物理数据，重新录制；若只是换文字/声音则应可复用 |
| 时长超出 | 降低帧数，或录制更长Take；`帧数/FPS`是实际秒数 |
| 改了字段但没变化 | 点击该页“应用”；手改v2 JSON后主动加载；三维字段不影响二维 |
| 点到黑边/拖动偏移 | 操作真实画面区域；预览按宽高比显示，黑边不属于场景 |
| 物体无法编辑 | 返回“编辑布置”；确认是初始对象且未锁定；运行中新生物体只读 |
| 碰撞没分裂 | 在调试页看`rule_rejected`、标签/规则挂载、保护期、动态上限与出生空间 |
| 没声音 | 检查开关/音量，应用后试听；查`audio.error`；密集接触可能被声音限流 |
| 生产失败 | 查任务`status.json`及日志；确认Take、Python/FFmpeg、源WAV、后端支持；用新任务名重试 |
| AI版本冲突 | 读取最新`scene.current.json`，重新评估后用新ID与最新revision提交 |

旧版入口保留为`preview.cmd -Legacy`及`render.cmd`；旧按键、文件监听和无声导出只属于旧版，不能和新工作台协议混用。
