# 对象、机制、特效与时间轴规范草案

日期：2026-11-13。状态：配套设计，接口和格式待实施；不能当成当前软件已有能力。

## 1. 数据和运行时类型

| 概念/类型 | 持有内容 | 实现建议 |
|---|---|---|
| SceneDocument | schema版本、场景ID、修订号、对象、机制、表现绑定、导出预设 | JSON持久化；校验后转为运行时数据 |
| ObjectSpec | 稳定ID、名称、标签、形状、初始变换、物理属性、外观、规则引用 | 数据记录，避免为每种特效组合建立物体子类 |
| ObjectHandle | 稳定ID与当前物理节点/显示节点引用、代数、生命期 | 只在运行时存在，不序列化Godot实例ID |
| World2D / World3D | ID到节点的映射、原生世界、接触采集、动作提交 | 分别继承Node2D/Node3D，通过相同方法协议被上层调用 |
| MechanismRule | 规则类型、启用状态、目标过滤、条件、参数与优先级 | 独立规则脚本；注册表只列实际实现的类型 |
| EffectPreset / AudioPreset | 视觉或声音参数、资源引用、时间域、采样版本 | 可共享预设＋少量对象覆盖，不在每个球上复制整套资源 |
| Take | 初始快照、轨迹、生命期、事件、时间映射、版本摘要 | 正式回放与生产的权威输入 |
| ProductionJob | 输入快照、Take、表现覆盖、输出规格与状态 | 任务创建时冻结，不指向可变的活动数据 |

编辑时以SceneDocument为准，模拟时以运行状态为准，回放时以Take为准。不能每帧把运行中的坐标写回初始布局。

球、方块、墙、斜坡是形状与物理模式的组合，不需要各自复制“分裂球”“发声球”“发光球”的继承树。Godot适配器可创建RigidBody或StaticBody，再挂碰撞体与显示节点；不强行给二维和三维节点设计同一个空间基类。

类型注册表只需提供：类型ID、支持维度、字段类型/范围/默认值、修改影响、参数验证与创建函数。普通字段自动形成属性表，复杂操作再增加专用小面板，不先建设通用插件市场。

### 物体类、机制类与特效类如何拓展

| 类/协议 | 实际类型或实现 | 最小接口 |
|---|---|---|
| ObjectSpec＋对象工厂 | Circle/Rectangle的二维形状；Sphere/Box的三维形状；Boundary/Sensor物理模式 | validate(spec)、create(spec)、read_state(id)、dispose(id) |
| MechanismRule | SplitOnContactRule、HitStopRule；后续DespawnRule/ForceRule | validate(params)、evaluate(event, context)、reset() |
| EffectRenderer | BurstEffect、ImpactRingEffect、FlashEffect、TrailEffect；后续CameraShakeEffect | evaluate(trigger, age, context)、release() |
| AudioSystem | 程序化短音/本地音频预设，共用声音调度 | audition(preset)、consume(event)、mix(events, range) |
| Inspector字段描述 | 普通参数自动生成控件；布置手柄等为专用工具 | fields、ranges、units、change_impact |

表中是待实施的类/方法职责，非现有API。简单机制不需要再拆成十几个仅转发一次调用的类；有独立状态/生命周期时才建立独立组件。视觉效果的`evaluate`按指定年龄重建画面，不依赖上次调用已前进多少帧。

## 2. ObjectSpec字段

| 字段 | 含义与约束 |
|---|---|
| id / name / tags | id唯一且持久；Godot节点名不能代替ID；标签用于过滤规则与表现 |
| shape | primitive、radius或size；线段有端点和thickness；形状声明支持2D/3D |
| transform | 初始位置、旋转；二维编辑角度用度，内部转弧度；三维编辑角度用欧拉度，录制用四元数 |
| physics | dynamic/static/sensor、质量、速度、阻尼、摩擦、恢复系数、层与掩码、CCD |
| appearance | 颜色、材质引用、描边、层级；与物理材质分开 |
| mechanisms | 对象启用的规则ID或规则预设引用 |
| editor | 编辑锁定、分组、仅编辑器可见的辅助信息；不改变求解 |

二维首版沿用现有逻辑坐标，单位明确为逻辑px、px/s；三维使用m、m/s。场景尺寸与导出分辨率分别保存；提高视频分辨率不放大刚体或重力。不要直接把二维的450重力数值搬到三维。

更新尺寸时从形状数据重建/调整显示和碰撞几何，避免只缩放Mesh留下旧碰撞体。三维模型装饰可以与碰撞体不同，但必须明确显示实际碰撞体，不能默认当成完全吻合。

首版2.5D定义为真实三维刚体＋正交相机；二维物理映射三维外观若以后需要，单独增加表现适配器，不伪装为已经具备的模式。

## 3. 机制：触发、条件、动作、表现

规则只根据事件和只读状态产生动作。物理响应、玩法动作、声音与粒子分别处理：

```text
原生求解/接触 → 标准事件 → 条件判断 → 动作候选
→ 批次校验与冲突消解 → 提交物理变更 → 已确认事件 → 声音/粒子/顿帧
```

小接口建议：

```text
World.load_scene(document)
World.capture_state() -> state
World.apply_actions(batch) -> committed_events
Mechanism.evaluate(event, readonly_state) -> actions
Presentation.consume(committed_event)
Replay.seek(presentation_time)
CommandService.execute(command) -> result
```

动作优先级明确：同一对象同一批次不能同时销毁两次；多个替换动作按规则优先级与稳定ID消解，并记录被拒原因。音效失败不回滚已发生的物理接触；粒子关闭不禁用分裂。

### 接触事件

统一事件包含：event_id、pair_id、contact_episode_id、接触阶段enter/stay/exit、双方稳定ID/标签、sim_tick、presentation_time、接触点、法线、可用的冲击指标、来源与数据能力。contact_episode_id标识一轮连续接触，同一对物体分离后再次碰撞产生新episode，因此音效去重不会吞掉真正的下一次撞击。

接触成立必须来自物理适配器，不能由画面上的两个圆看似接近来猜。若后端不能可靠提供预求解速度或真实冲量，字段标为缺失并声明能力；不能用反弹后的速度冒充入射速度，也不能把未知冲量默认为0而静默拒绝规则。

物理层保留真实接触；机制层决定是否接受；声音层才做听觉上的去重与限流。球球的双方通知先归为同一物体对，接触持续期间不能每个tick重新当成一次撞击。

### 分裂事务

1. 在求解回调结束后收集同一物理步的接触快照，先评估双方，再修改世界。
2. 对父ID＋规则ID去重；墙角接触可有多个来源，父球只替换一次。
3. 保护期内不分裂；保护到期仍存在的接触重新评估；已经离开的接触不补发。
4. 预留容量和子球出生空间，校验几何不重叠/不穿墙。无法放置时按明确策略延后或跳过并记录原因，不暗中把中心强行夹到墙边。
5. 原球退役与全部子球出生作为一个提交，随后产生父子关系、变色、音效和特效事件。
6. 子球总数按用户规则解释。1→2就是移除1个、创建2个；上限不足时首版整次跳过，不静默减少总数。

尺寸策略独立配置：保持尺寸属于玩法；二维等面积可用`r_child=r_parent/sqrt(k)`，三维等体积可用`r_child=r_parent/cbrt(k)`。这些公式只控制面积/体积，不能据此宣称分裂过程自动满足全部物理守恒；质量、附加冲量、出生空间仍要独立处理。

## 4. 时间与运行状态

| 时间 | 推进依据 | 顿帧 | 手动暂停 |
|---|---|---|---|
| 模拟时间 | sim_tick / physics_hz | 停止 | 停止 |
| 成片时间 | 视频播放/录制的时间轴 | 继续 | 停止 |
| 界面时间 | 用户交互与任务轮询 | 继续 | 继续 |

首版全局顿帧；局部物体慢动作后续再做。不要继续用全局SceneTree.paused冻结所有面板、声音与生产任务。统一Clock决定物理是否推进，并把成片时间和模拟时间提供给表现系统；面板始终可操作。

顿帧写入时间映射段：正常段推进模拟与成片时间；hold段成片时间前进而模拟tick不变。同批次多次分裂合并一段顿帧，不按球数量无限叠加。

单物理步准确推进一次求解；单成片帧按1/output_fps移动播放头，在hold段可以不推进任何物理步。改变输出FPS只改变对已有Take的采样，不重定义模拟频率。

状态转换：编辑→模拟/录制；模拟→暂停/重置；录制→停止并生成Take；回放→只读寻帧。回放后直接“接着算”不承诺连续一致，因为姿态记录没有保存求解器全部接触缓存。若要继续实验，显式从该帧创建新初始场景与新Take。

## 5. Take与寻帧

| 数据 | 最低要求 |
|---|---|
| manifest | 格式版本、场景快照、simulation_hash、Godot/后端版本、物理频率、采样说明 |
| states | 实际采样的位置/旋转、对象ID、必要的速度；记录求解提交后的状态 |
| lifecycle | 出生/退役时间、形状尺寸、父子关系、代数、运行时对象定义 |
| events | 原始接触及机制结果、动作提交、表现触发、唯一event_id与随机种子 |
| time_map | sim_tick与presentation_time的对应关系，含顿帧段 |
| resources | 使用的预设、音频/字体/材质版本与内容摘要 |

通过sim_tick计算模拟时间，不累加浮点delta作为长期权威时间。成片时间采用整数微秒或明确的有理数时间基准，避免反复四舍五入累积漂移。

回放使用无求解的显示对象或彻底停用动态物理和机制；不重新消费事件去创建额外子球。按生命期决定对象集合，退役时刻原球不可见，子球按同一事务生效。

二维角度插值处理±π环绕；三维旋转使用四元数插值。只在同一对象连续生命期内插值，不能在父球与子球之间插值；碰撞拐点或离散事件边界使用分段采样，避免把球插值穿过墙面。物理采样频率与导出FPS分开，常用120/240Hz记录、30/60fps输出。

先用分块JSONL＋少量索引实现易检查版本；长轨迹再采用紧凑二进制。分块按时间索引，寻帧不应每次从第0帧逐帧扫描。状态快照用于展示恢复，不等同于物理求解器检查点。

容量需要实测：按200个物体、60秒、240Hz、每对象每次64字节估算，原始状态约175.8MiB，尚未含事件和索引；JSON会明显更大。限制录制时长、写盘分块，不能无限保存在内存列表中。日志面板用有界窗口，完整调试日志可另存文件。

### 什么修改需要重新录制

| 影响simulation_hash | 仅影响presentation_hash |
|---|---|
| 初始姿态/速度、形状尺寸、质量、重力、摩擦/弹性、碰撞过滤、分裂规则、顿帧时间映射 | 颜色、材质外观、文字字体、灯光、相机、声音预设、纯视觉粒子 |

左列改变后标记Take过期，不能默默拿旧轨迹代表新规则。右列允许复用Take，重新渲染/混音；帧缓存和最终视频相应失效。若相机或表现参数被特殊规则用于物理判定，依赖必须显式归到simulation_hash，不能靠字段名称猜。

## 6. 粒子、拖尾、音效的准确回放

每次特效触发记录event_id、对象ID、位置/方向、预设、种子、强度、触发时间和时间域。首版粒子按种子、粒子序号、年龄直接求值：

```text
age = selected_clock(now) - selected_clock(event_time)
position(age) = start + initial_velocity * age + 0.5 * acceleration * age²
color / size / alpha = configured_curves(age / lifetime)
```

这些碎屑属于视觉效果，不是额外刚体。若需要碎片真的影响碰撞，就建立独立物体并进入轨迹记录，不能只换一个粒子开关。

拖动时间轴时重建仍在寿命内的事件，按age还原粒子；拖尾按Take历史位置生成，不能用“当前摄像机已经显示过哪些帧”的残留。动画Shader使用显式传入的成片/模拟时间，不使用不可回退的全局运行TIME。

GPU粒子只固定seed并不足以保证任意seek后与连续播放相同；后续模式需要从确定起点重算、粒子状态烘焙或逐帧缓存，并验证后端支持。视觉风格一致也不等于不同显卡逐像素完全相同。

声音组件参数：触发事件/标签、预设或音频资产、音量、音高、强度映射、随机变化范围、最短间隔、最大并发、声像与总线。连续碰撞限流仅作用于声音，不删除物理事件。

正常播放消费`(上一时刻, 当前时刻]`的声音事件；首次播放单独包含t=0事件，避免遗漏开场或出生音。seek默认静音并停止旧声部，单独提供“试听此事件”。离线混音用`round(presentation_time × sample_rate)`定位采样点，预览与生产使用同一音频资产/参数；不能录电脑扬声器当作正式音轨。

默认工作音轨48kHz PCM；成片编码AAC。处理密集事件的限声部、削波、音量与结尾裁切/淡出；粒子和音频各自使用独立随机源，不能扰动分裂方向的随机序列。

## 7. 统一命令入口与参数调试

命令格式示意：

```json
{
  "command_id": "cmd_000127",
  "base_revision": 12,
  "op": "object.update",
  "args": {"object_id": "ball_A", "changes": {"transform.position": [240, 420]}}
}
```

返回command_id、ok、revision、影响对象、是否使Take过期、字段级错误和生成文件路径。同一command_id不得重复执行；过期base_revision返回冲突，让AI读取最新场景后重新提交。

| 命令组 | 最小操作 |
|---|---|
| scene | load / save / patch / validate |
| object | add / update / remove / duplicate / arrange |
| component | enable / update / preset |
| simulation | play / pause / step / reset |
| take | record / stop / load / seek / range |
| render | enqueue / cancel / status |

本地命令队列用临时文件写完后原子改名，执行后写结果文件；AI可读取返回数据和预览截图。面板直接调用同一CommandService。首版不需要额外HTTP/MCP服务。

属性字段标记三类操作：`live_presentation`立即预览，`requires_reset`修改初始数据并重置，`read_only_runtime`只读观察。回放中的世界坐标属于第三类。撤销/重做按编辑事务组织；布局批量复制一次撤销，不让每个鼠标移动采样占一条历史。

可调试字段至少包括对象ID/代数、世界坐标/速度、碰撞体、接触来源、机制接受/拒绝及原因、待提交动作、声音/粒子event_id、双时间与当前运行模式。日志可按对象、规则、事件类型过滤，并跳到对应成片时间。

## 8. 视频任务与文件边界

生产目录示意：

```text
outputs/jobs/<job_id>/
  scene.snapshot.json
  job.json
  take_reference.json
  resources.manifest.json
  frames/
  mix.wav
  final.mp4
  validation.json
  logs/
```

独立Godot进程载入冻结的Scene快照与Take，真实渲染干净Stage Viewport；FFmpeg混音/编码。输入文件在任务期间不能由活动编辑器覆盖。取消任务只结束本任务进程，保留可诊断的中间产物，不误停预览。

首版单任务串行。任务状态为排队、校验、渲染、混音、编码、验证、完成/失败/取消。进度注明当前阶段，不能用“已渲染100%”冒充视频已经编码成功。

输出帧数N与FPS确定时长`T=N/FPS`，音轨裁切/补齐到T。核对实际媒体尺寸、FPS、完整解码帧数/时长、音轨存在与非静音；用已知脉冲测试音检测事件对齐。是否有声音不能只看文件里是否存在一条全静音音轨。

## 9. 建议代码位置（待建立）

```text
src/
  document/       # 场景模型、迁移、校验、参数描述
  commands/       # AI与面板共用命令、撤销与回执
  runtime/        # SceneSession、时钟、事件、对象ID

  mechanisms/     # 规则与动作提交
  presentation/   # 显示、相机、文字、声音、粒子、拖尾
  takes/          # 记录、分块存储、寻帧与播放

assets/presets/   # 材质、音效、粒子、物体与机制预设
```

这只是职责边界，不要求先建立全部空类或空目录。每个阶段只增加实际使用的模块。现有`scripts/`逐步变为兼容入口和验证夹具的调用层；每次迁移跑对应基线，避免一次重写全部逻辑。
