## 新电脑与AI接手

源码开发：克隆正式远端，运行根`SETUP_WORKBENCH.cmd`恢复工具，再运行`START_WORKBENCH.cmd`或`OPEN_EDITOR.cmd`。首次恢复需要联网；下载由锁定SHA校验，依赖和缓存写在工程盘。

离线使用：完整解压Release ZIP，运行`VERIFY_PACKAGE.cmd`检查运输完整性，然后启动。源码克隆没有MANIFEST或原片，不能用完整包校验器验证Git状态；用`git status`及对应模块验证。

AI读取`START_HERE.md`、根/子工程`AGENTS.md`、FILE_INDEX、需求决策和LESSONS后接续工作。日常只有根`.git`，不要在子工程恢复或创建另一个`.git`。旧三个仓库的bundle是归档材料，非日常克隆入口。

## 1.0定义与后续发布

1.0冻结现有已验收功能：原生2D/3D、正交2.5D观感、物体/机制/文字/声音/特效面板、AI文件命令、Take回放和视频生产。真实碎裂/耐久、严格四层解耦等仍为待办，版本号不改变能力边界。

后续在功能分支做最小改动，更新FILE_INDEX/CHANGELOG并运行相关验证；未经用户要求不自动推送/发布。用户已明确授权本轮上传main和发布1.0。`v1.0`固定，修复应使用新提交和新版本，不能覆盖标签冒充原版。

完整发布流程：提交源码 → 创建带说明标签 → 打包新目录/ZIP及清单 → 核对文件/版本/哈希 → 推送分支和标签 → 上传对应Release附件并核对远端。MANIFEST不包含自身；压缩包SHA在旁边，避免循环引用。

完整包的Git bundle可以恢复源码历史；普通ZIP工作区不自动含`.git`。未来打包只从当前根仓库导出最新历史，早期子工程bundle原样保留。正式工作区开始编辑后，原交接MANIFEST可能不再匹配；这是已记录的开发变化，新Release重新生成清单。
