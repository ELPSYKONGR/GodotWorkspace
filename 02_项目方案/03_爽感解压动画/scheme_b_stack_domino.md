# 方案 B：倍增链路·破碎多米诺

## 定位

这是一个 15–24 秒、9:16 竖屏物理动画。主问题是：“一颗球触发机械闸门释放的预装球后，能否触发完整多米诺链并击碎玻璃？”观看路径为：

`触发闸门 → 预装球释放 → 机关连续触发 → 玻璃破碎 → 结果计数 → 循环`

数量增加必须改变后续画面，结果必须由真实事件兑现，避免“数字变大但没有目标”。

## 规则和对象

对象：`seed_ball` 主球、`release_gate` 释放闸门、`preloaded_ball` 预装球、`domino_tile` 多米诺牌、`glass_block` 玻璃块、`collector` 收集器。

1. 主球进入释放闸门的传感器，闸门移除后释放预装在储料区中的 2/3/4 颗球；球的数量变化来自储料区，不是碰撞凭空复制。
2. 每个闸门只允许触发一次；预装球在闸门打开后受重力和初始出口速度影响运动，最小间距为 1.25 倍半径。
3. 第一颗球撞击多米诺后，只允许相邻牌在 0.08–0.16 秒延迟内倒下；没有前置碰撞不能跳变。
4. 玻璃按“完整→裂纹→破碎”状态机处理；耐久为 0 后才生成碎片和破碎音。
5. 结果记录 `broken_count >= target_count`、全部球进入收集器或截止时间到达，并保存 `result_reason`。
6. 结果卡停留 1.0–1.4 秒，保留最后一颗球和真实计数后循环。

## 18 秒分镜

| 时间 | 事件 | 留存作用 |
|---|---|---|
| 0.00–0.80s | 首球、玻璃、`1→4` 标签和第一次移动 | 立即理解规则 |
| 0.80–3.20s | 第一次传感器接触，预装球排队释放 | 验证机械释放 |
| 3.20–6.20s | 第二个闸门被球触发，计数按实际释放结果增加 | 期待规模扩大 |
| 6.20–9.40s | 第一块多米诺被撞，链式倒下 | 连续触发爽点 |
| 9.40–12.80s | 球撞击玻璃，裂纹扩散 | 期待全部击碎 |
| 12.80–15.80s | 耐久快速下降，出现一次差一点失败 | 形成反转 |
| 15.80–17.20s | `37/48 破碎`、耗时、原因 | 兑现标题 |
| 17.20–18.00s | 卡片缩小，主球回到首帧 | 无缝循环 |

## 数据层配置

建议增加 `scene_stack_domino.json`，文字、字号、帧率、颜色和目标数量均为配置：

```json
{
  "scene_id":"stack_domino_v1", "seed":260811, "duration_s":18, "fps":60,
  "canvas":{"width":1080,"height":1920},
  "text":{"title_size":54,"counter_size":42,"result_size":64},
  "multiplier":{"values":[4,4],"cooldown_s":0.55,"max_live_balls":48},
  "domino":{"count":32,"spacing":42,"trigger_delay_s":0.11,"angle_deg":72},
  "glass":{"count":48,"hp_each":1},
  "physics":{"fixed_dt":0.008333,"gravity":920,"restitution":0.76,"friction":0.18},
  "audio":{"enabled":true,"master_db":-8}
}
```

事件日志必须包含：`spawn`、`gate_close`、`gate_open`、`domino_hit`、`glass_hit`、`glass_break`、`collector_update`、`result`。每个事件带时间戳、对象 ID、来源 ID 和结果值；固定种子后应能重现同一结果。

## 物理层

- 用固定时间步 1/120 秒计算碰撞，渲染输出 30/60fps；高速球启用连续碰撞检测，避免穿透。
- 多米诺的角度由动态刚体积分得到；只有碰撞回调首次收到足够冲量时才记录 `domino_hit`。
- 玻璃收到球或多米诺的碰撞冲量后进入 `glass_hit`，随后从物理空间移除并记录 `glass_break`；没有接触就不会破碎。
- 同一对象同一事件 ID 只处理一次，防止重复计数。
- 任意连续 1.2 秒无进展时，显示下一批释放、门状态或剩余耐久，避免中段停滞。

现有实现映射：`src/data/config.py` 放参数校验；`src/core/stack_domino.py` 使用 Pymunk 处理闸门、球、多米诺、玻璃和收集器碰撞；`src/data/scene.py` 保存轨迹和事件；`src/rendering/renderer.py` 读取动态多米诺角度和破碎事件；`src/rendering/audio.py` 读取事件；`src/rendering/exporter.py` 做帧率、音频轨和解码检查。

## 渲染和视觉

背景使用 `#111827`；主球用青/橙高饱和色；玻璃用冷白/蓝灰；结果状态只用一种强调色。主轨道 8px、裂纹 3px、计数框 2px，同一层级线宽固定。顶部 180px、底部 230px 为安全区。密度曲线为“0–3 秒稀疏、6–13 秒增密、13–16 秒碎片爆发、结果阶段清空”。结果卡固定在下三分之一，显示真实计数、用时和原因。

## 音频事件

- `spawn`：短促上扬音，音高随倍数变化，限制 2–4 个音阶。
- `domino_hit`：木质轻击，连续间隔 80–120ms；超过 12 次自动降低 3dB。
- `glass_hit`：高频轻裂；`glass_break`：低频冲击加玻璃碎裂，持续不超过 220ms。
- `collector_update`：每 8 个破碎块触发一次提示音，不对每个碎片发声。
- `result`：成功用短上行和弦，未完成用低音停顿。

音频由事件总线生成，提供静音版和低音量版；原片未逐条试听时，不把原片音效写成事实。

## 自动化流程

1. 读取 JSON 并校验颜色、字号、帧率、时长和对象上限。
2. 固定种子模拟，导出事件日志：首次事件、最大事件间隔、破碎率、结果时刻。
3. 自动验收：穿透数为 0、重复事件为 0、结果计数一致、最后 0.4 秒有结果或卡片、无黑帧。
4. 先输出低码率预览，按“首屏可懂、事件密度、结果兑现”筛选。
5. 通过后渲染 1080×1920、60fps，并生成 30fps 和静音版。
6. 只替换标题、倍数、颜色和目标数量生成 A/B 组；每次只改一个变量。
7. 归档 `scene.json`、`events.json`、`preview.mp4`、`master.mp4`、`thumbnail.png` 和 `validation.json`。

## 参数、成本和难度

| 变量 | A | B（首发） | C |
|---|---:|---:|---:|
| 释放闸门次数 | 2 | 3 | 4 |
| 玻璃层数 | 24 | 48 | 96 |
| 多米诺间隔 | 0.08s | 0.11s | 0.16s |
| 球体上限 | 24 | 48 | 72 |
| 结果停留 | 0.8s | 1.2s | 1.6s |

首发使用 B 组。首次开发约 2–4 个工程日，难度中等；主要风险是高速碰撞、倍增遮挡和碎片性能。参数化后单条 18 秒成片约 20–80 元，多轮调参约 80–200 元；1080×1920 本地渲染约 2–8 分钟。批量生成 20–100 条候选后人工挑选前 10%。这是工程预算区间，不是收益承诺。

## 验收清单

- [ ] 标题数字等于事件真实结果。
- [ ] 释放闸门无重复触发，球体无穿透和异常重叠。
- [ ] 每块多米诺都有前置碰撞事件。
- [ ] 玻璃先裂后碎，碎片不遮挡计数。
- [ ] 0–2 秒出现主球、目标和第一次变化。
- [ ] 任意 1.2 秒都有进展或状态变化。
- [ ] 结果卡停留至少 1 秒，尾段无空白。
- [ ] 30/60fps、静音/有声版本均可导出，路径不依赖 C 盘。

方案 A 负责圆环、缺口和逃逸的空间悬念；方案 B 负责倍增、链式和破碎的密度与音画冲击。两者共享数据层、事件总线、字体/帧率配置和自动验收器，只替换对象规则与镜头布局。首轮各做 10 条，对比 2 秒留存、平均观看秒数、重播率和评论中的规则理解。
