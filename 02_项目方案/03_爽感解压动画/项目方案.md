# 五、项目三：爽感解压短视频

评估日期：2026-11-11。本文摘自总报告；素材拆解、全部预算假设、来源访问状态与完整成本表请一并阅读总报告。


### 前景与变现

优势是跨语言、规则简单、试验速度快、可以自有资产批量生产。劣势是容易同质化，用户可能只消费这一条，关注与购买意愿较弱。国内短视频不应默认“播放量＝收入”。可探索有合适品牌的软性定制、制作服务、可授权素材；纯流量分成必须以自己的账号权限和实际到账验证。

### 先用能精确控制规则的制作方法

**A 路线：2D 物理模拟，优先。** 样本的主体几乎在一个平面里。用 Pymunk 等二维刚体库计算小球和旋转边界，Pillow／其他绘图库绘制，再用 FFmpeg 编码。一个确定的随机种子可以复现结果；数值、颜色和开口时间可以批量试验。不需要每个镜头付一次 AI 视频生成费。[Pymunk 官方仓库](https://github.com/viblo/pymunk)已核验为 MIT，元信息与 README 保存在补充来源文件，商用前核查具体版本。

**B 路线：Blender。** 当题材需要真实材质、切割、破碎、立体轨道、液体或反射，使用 Geometry Nodes、刚体与 Python，先低清预览和烘焙，再后台渲染。并非所有效果都能靠 Geometry Nodes 自动完成；复杂流体、断裂和碰撞声音需要相应实现。官方仓库已核验，官网许可和命令行手册本次未成功访问。[S8]

**C 路线：纯生成视频。** 能快速探索概念，但很难稳定实现“每次碰撞准确分裂、球不穿墙、数量连续递增、结尾按时释放”。这种规则内容不建议以纯生成视频为主。AI 更适合前期想法、背景或材质设计。

### 实施难点与自动化

分裂若不设上限会指数增长，既难看又会拖垮模拟。需要每次碰撞去重、出生冷却、最大球数、稳定步长和明确的结尾策略。密集碰撞采用上限后的视觉替代或分段烘焙，不能承诺无限真实物理。

实现“参数→模拟→逐帧渲染→碰撞音效→字幕→编码→质量检查→待发布包”后，模板内 85%—95% 的步骤可自动运行；新规则设计和选片仍由人工做。量产后每条约 0.2—1 小时人工，不包含首次模板开发与较长渲染等待。是否稳定，必须用连续多条、不同种子试跑确认。
