# 迁移与打包说明

用途：在另一台Windows x64电脑恢复同一任务、运行工作台并让其它AI继续开发。当前运行包保留研究项目原层级，不能只拿走Godot目录后仍期待原片链接有效。

正式仓库现为`https://github.com/ELPSYKONGR/GodotWorkspace.git`，1.0（`v1.0`）。任务根统一管理所有源码；本地正式目录由用户指定为`D:\codex\deliveries\RelaxVideo_Handoff_20261113`。源码克隆先运行根`SETUP_WORKBENCH.cmd`；完整离线资料从Release下载。日常开发不恢复旧子仓库，下面的bundle操作仅用于历史归档，详见[仓库说明](../../../docs/仓库与版本管理.md)。新包从根单仓库导出最新bundle，旧Godot/Python bundle可继续保留。

## 1. 必要工具与路径

正常使用先读任务根`START_HERE.md`，双击`START_WORKBENCH.cmd`；工程内`workbench.cmd`同样能启动默认预设。所有入口通过`tools/common.ps1`和`runtime_environment.ps1`定位当前目录。

| 工具 | 包内位置 | 用途 |
|---|---|---|
| Godot 4.7.2 Windows x64标准版 | `.runtime/godot/`，保留GUI、console和`_sc_` | 原生编辑、物理解算、预览和逐帧渲染 |
| CPython 3.12.10 embeddable | `.runtime/python/python.exe` | 当前生产脚本使用标准库，无兄弟venv依赖 |
| Pillow 11.3.0 | Python的`Lib/site-packages/` | 旧版媒体抽帧/联系表辅助；不是所有历史Python原型依赖全集 |
| FFmpeg 7.1 Gyan构建 | `.runtime/ffmpeg.exe` | H.264/AAC生产与完整媒体解码 |
| MinGit 2.56.1 | `.runtime/git/cmd/git.exe` | 离线查看、恢复和提交源码历史，不是渲染依赖 |
| 安装档案 | `.runtime/downloads/` | 锁定ZIP/wheels，可离线恢复以上工具 |

版本、官方/PyPI来源、SHA-256及校验来源在`config/runtime-lock.json`；部分SHA是下载后实测而非官方签名校验，清单已逐项注明。许可正文见`docs/third_party/`、`.runtime/licenses/`和MinGit自带目录。

系统、驱动、PowerShell和中文字体不在包内。其它系统架构需另配引擎/运行工具，不能直接用此Windows包。普通目标电脑放非系统盘；指定远程4080 SUPER电脑放非C/D盘。本次未实际操作远程电脑。

## 2. 配置与离线恢复

配置优先级为**进程环境变量 > 工程`.env` > 工程内默认路径**。四个可覆盖变量见`.env.example`：`VIDEO_LAB_GODOT`、`VIDEO_LAB_RENDER_GODOT`、`VIDEO_LAB_PYTHON`、`VIDEO_LAB_FFMPEG`。默认不用创建`.env`；相对路径以Godot工程根解析。`.env`不执行表达式，不展开变量，不支持行尾注释。

迁移包不复制本机`.env`。若从已经加载旧工程环境的终端启动新副本，先清除这四个进程变量，或另开终端，否则显式覆盖会继续指向旧位置。APPDATA、LOCALAPPDATA、TEMP和TMP由启动器重定向至当前工程`.runtime/`；引擎编辑器使用`_sc_`便携模式。系统/驱动自身的写入不属于应用目录控制范围。

在Godot工程目录恢复缺失工具：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/setup.ps1 -DevTools
```

缓存齐全时无需联网；缺少锁定档案时才下载。脚本会校验缓存SHA，不把“文件存在”当作内容正确。`-SkipImport`可只恢复工具；完整启动前仍需正常导入Godot工程。无需pip、uv或全局Python。

历史`relaxing-physics`的venv和系统工具没有硬复制。若后续需要重跑，读取其`requirements.lock`、setup和源码，在目标电脑重建；不要把旧`pyvenv.cfg`里的D盘绝对路径当作便携依赖。研究辅助脚本的第三方包同理，已有报告/原片阅读不需要重装它们。

## 3. 内容、场景与证据

包包括所有研究主目录的资料/原片、当前源码、主要旧成片、当前Godot 2D/3D样片、两个代表生产任务的冻结输入、两份Take、抽帧、验收报告和版本历史。排除旧venv、浏览器/编辑器缓存、活跃控制收件箱、机器`.env`、重复中间PNG帧和早期临时调试脚本。

交接场景保存在`config/handoff_current_scene.json`，来源和版本写入总包MANIFEST；它是确认保存的初始布局。没有移植活动求解器内部状态、未保存录制、当前选择、撤销历史或排队任务。旧任务日志可能保留原机器路径，仅作历史证据；新任务使用当前工程路径。

外部PCM WAV若被选为交接场景音色，打包器会复制到工程`assets/handoff/collision.wav`并使用`res://`引用。历史生产任务的绝对WAV引用不自动承诺可重渲染，需明确重定位并重新验证。

主参考原片在任务根`09_50x50扩展/original_videos/`：B站57、抖音50。全归档189份媒体副本/109个作品ID，含图文故事和重复文件；详见`reference_media_inventory.json`。本次只盘点文件/大小/哈希，没有把所有文件重新完整观看或试听。

## 4. 完整性和版本恢复

总包`MANIFEST.json`只列相对路径、字节数、SHA-256、源码版本和初始场景来源，不列自身哈希。ZIP旁的`.sha256`校验完整压缩包。解压后、首次运行前双击`VERIFY_PACKAGE.cmd`；开始编辑后的内容变化应当被校验器报告。

Git bundle不包含便携依赖、原视频等Git忽略的大文件，完整包和bundle应配合保留。包内已含源码，不需要克隆才能运行。若要恢复带历史的工作副本，可在**新目录**运行：

```powershell
$git = '.\06_本地部署\godot-video-lab\.runtime\git\cmd\git.exe'
& $git clone .\version_history\godot-video-lab.bundle .\restored-godot-source
& $git -C .\restored-godot-source log -5 --oneline
```

研究任务和旧Python的bundle用同样方法恢复。`*-working.patch`仅保存已跟踪文件的未提交改动；未跟踪源码仍在完整包的原工程目录，并在MANIFEST的仓库记录中列明。要恢复打包时完整工作状态，可把包内对应源码叠加到新克隆的匹配基线上；或检视patch后应用，并补回列出的未跟踪文件。普通解压目录已经包含打包时的源文件，不应再次机械套patch。旧Python仓库本轮没有擅自提交或重置这些历史改动。

## 5. 重新打包与验证

`tools/build_handoff.py`只依赖Python标准库。它创建一个新的包目录；目标必须在来源目录之外，且不得已经存在。保留原目录层级、复制必要工具/资料、导出Git bundle、保存初始场景、逐文件做SHA校验，再可选生成ZIP和ZIP校验值。

```powershell
. .\tools\common.ps1
& $PythonExecutable -B tools/build_handoff.py `
  --destination E:/Exports/RelaxVideo_Handoff `
  --archive E:/Exports/RelaxVideo_Handoff.zip
```

默认研究根由脚本位置定位。可用`--source`显式指定整任务根，用`--scene-snapshot`指定一份已确认保存的初始场景；没有运行工作台时应优先选保存文件，避免把旧发布状态误当最新。校验命令：

```powershell
& $PythonExecutable -B tools/build_handoff.py --verify E:/Exports/RelaxVideo_Handoff
```

验证应在独立副本进行，尤其Host测试会写默认文件桥。先做便携环境检查、必要模块检查，再真实录制/生产一个短片并检查完整解码/声音。迁移不能只以能打开窗口为成功。

Godot只使用已知有效的CLI参数；`--license`不是这个版本支持的选项，可能启动默认工程。许可使用已保存官方文本；版本检查用`--version`，参数查询用`--help`。
