# 解压动画方案设计

本文对应当前已经实现的六种二维物理动画机制。基础三种方案共用圆环、旋转挡板、碰撞音效和末段释放；新增 `ring_escape` 使用多层旋转缺口，`stack_domino` 使用机械闸门释放预装球并触发多米诺和玻璃破碎，`versus` 让两条完全相同的通道比拼指数增长。它们由确定的物理模拟和程序绘图生成，可以在普通电脑的 CPU 上运行，不需要调用付费视频生成模型，也不需要 NVIDIA 显卡。

当前是可调整、可预览、可导出的视频工作台。六种方案已经实现；文末的其他题材是后续方向。

## 1. 六个方案如何区别

| 方案 | 核心变化 | 观众等待什么 | 适合的文案方向 |
|---|---|---|---|
| 碰撞增殖 `multiply` | 符合条件的碰撞产生新球，密度逐渐增加 | 还能装下多少、何时释放 | “越碰越多”“最后能有多少颗？” |
| 旋转逃逸 `escape` | 固定数量的小球寻找旋转缺口，逃出数逐步增加 | 下一个谁能出去、最后还剩几个 | “谁能逃出去？”“缺口转过来了” |
| 小球雨释放 `rain` | 从上方持续尝试投球，容器逐渐积满 | 会不会接不住、堆到哪里 | “接得住这场小球雨吗？” |
| 环形缺口逃逸 `ring_escape` | 多层环保持固定半径并旋转缺口，小球受碰撞后寻找出口 | 下一层能否穿过、最终能逃出几颗 | “还能穿过第几层？” |
| 倍增链路 `stack_domino` | 主球接触闸门后释放预装球，再由真实碰撞触发多米诺和玻璃 | 闸门能否打开、链条能否传到玻璃 | “这一波能推倒多少？” |
| 双通道指数赛 `versus` | 两条同尺寸通道同时指数增殖，先到容量的一侧获胜 | 一颗球能不能追上已经成群的一侧、差多少秒 | “1 颗能追上 70 颗吗？”“领先 0.18 秒” |

三种基础方案默认都是 24 秒：前 20 秒积累过程，20 秒时打开边界，后 4 秒集中释放。新增两种方案使用各自的物理阶段和结果状态。

## 2. 基础机制：碰撞增殖 `multiply`

### 视觉过程

1. 少量彩色小球落入圆环，旋转挡板将它们拨起。
2. 小球碰到圆环、挡板或其他小球时，符合冷却条件的球尝试在附近产生一个新球。
3. 球的数量逐步增多，画面从稀疏变得拥挤，底部出现不断翻动的堆积。
4. 到达释放时间后，圆环打开、挡板移除，小球获得向外和向上的推动，再受重力影响落下。

爽点来自数量增长带来的预期，以及拥挤之后的集中释放。碰撞声与实际碰撞事件对应，画面和声音具有明确的因果关系。

### 当前规则

默认初始 6 颗、上限 460 颗、增殖冷却 1.1 秒。生成新球还要找到不重叠的空间；越拥挤，越容易生成失败。因此数量不会按固定指数无限增长，也不会保证达到上限。释放后停止增殖。

### 调参建议

- 想让增长更快：先减小增殖冷却，再适当提高挡板转速；观察是否过早拥挤。
- 想让密度更高：减小球半径或提高数量上限。球更小、数量更多会增加计算量。
- 想让最后的释放更明显：延后释放时间，为堆积保留时间，同时留出至少几秒展示结果。
- 想测试新的运动结果：改变随机种子；只改颜色和文字会保持原有运动。

## 3. 基础机制：旋转逃逸 `escape`

### 视觉过程

1. 一批小球在圆环里跳动，挡板继续搅动它们。
2. 圆环有一个约 40° 的缺口，缺口位置缓慢绕圆移动。
3. 小球靠近缺口时，可能恰好穿过，也可能错过，形成连续的小悬念。
4. 末段打开整个圆环，释放尚在模拟中的小球。

爽点来自可见目标与不确定结果：观众容易跟随某一颗球，等待它能否在下一轮逃出。相比增殖，画面数量逐渐减少，节奏更清楚，适合使用逃出计数。

### 当前规则

默认初始 48 颗，不增殖、不补球。缺口中心随 `ring_angle` 转动，其速度由挡板转速乘以 0.23 得到；当前还没有独立的缺口转速或缺口宽度编辑项。

小球离开圆心的距离超过“圆环半径 + 1.5 倍球半径”后，才计入逃出数并移出模拟。`escaped` 统计末段释放之前从缺口逃出的数量；末段全开后不再累计这个计数。`remaining` 是仍保留在模拟中的对象数，不等于当前仍位于圆环内部的数量。

### 调参建议

- 想让观众容易追踪：减少初始球数，适当放大球。
- 想让逃逸更密集：调整重力、挡板转速和随机种子，选出逃出过程分布较均匀的版本。
- 想突出最后几颗球：延后全开时间，让前段保留更多观察空间。
- 文案用 `{escaped}` 展示逃出数量；不要把 `{count}` 当成当前剩余数，后者是累计出生数量。

## 4. 基础机制：小球雨释放 `rain`

### 视觉过程

1. 默认先有 4 颗球，新的球从圆环上边缘内侧持续落下。
2. 挡板拨动落球，底部形成持续变化的彩色堆积。
3. 上方不断有新球进入，画面密度上升，产生“还装得下吗”的期待。
4. 末段统一打开边界，将累积的球释放出去。

爽点来自稳定的输入节奏、不断变高的堆积和突然清空的对比。它比碰撞增殖更容易解释：新增球来自上方投放，碰撞本身不会产生新球。

### 当前规则

默认上限 420 颗。程序每约 0.1 秒尝试投放一次，但入口附近被占用时会跳过，因此实际投球速度可能低于每秒 10 颗。当前页面没有独立的投放间隔控件。释放后停止投球。

### 调参建议

- 想要较细密的小球雨：减小球半径，同时确认球数上限和运行时间足够。
- 想要更明显的弹跳：改变重力和挡板转速；过高重力可能使堆积更快压紧。
- 想强调堆满过程：减少初始球数，并为释放前保留更长时间。
- 计数使用 `{count}`，表示已经投放并生成的累计数量。

## 5. 哪些内容可以修改

数据来源是 `config/presets/` 的六个 JSON 预设，以及编辑器保存的当前配置。页面提供常用配置和文字层编辑；更完整的物理与配色参数可在配置文件中调整。配置必须通过程序校验。

| 配置 | 当前支持 | 是否需要重新计算运动 |
|---|---|---|
| 文字内容 | 自定义文案、多文字层、显隐 | 否 |
| 文字样式 | 字体、字号、颜色、位置、对齐 | 否 |
| 动态文字 | `{count}`、`{remaining}`、`{escaped}`、`{time}`、`{phase}` | 否 |
| 输出帧率 | 24、25、30、50、60 fps | 否 |
| 输出尺寸 | 360×640、540×960、720×1280、1080×1920 | 否 |
| 配色 | 背景渐变、圆环、挡板、小球颜色 | 否 |
| 音频 | 开关、音量；碰撞事件合成音效 | 否 |
| 时长与释放时间 | 当前配置校验允许时长 1–60 秒，释放早于结束 | 是 |
| 物理规则 | 机制、初始球数、上限、球半径、转速、重力、增殖冷却 | 是 |
| 随机种子、采样率 | 种子固定可复现；数据采样率 30、60、120 Hz | 是 |

文字位置和字号以 720×1280 逻辑画布为单位，随输出尺寸等比例缩放。文字超出画布会提示调整，不会擅自缩小字号。可选字体来自本机和项目字体目录。

`count` 是累计出生数，`remaining` 是仍保留在模拟中的对象数，`escaped` 是缺口逃出数。`phase` 当前只有“累积”和“释放”两个状态。如果旋转逃逸希望显示“等待逃出”，可直接编辑该文字层的文案。`versus` 另外提供 `left`、`right`（两侧实时计数）、`winner`（“左侧”/“右侧”/“两侧”）和 `margin`（领先秒数，可用 `{margin:.2f}` 控制小数位）。

## 6. 数据与渲染怎样分离

物理层先计算固定采样率的轨迹，保存为 `scene.npz`：位置、颜色编号、计数、角度、释放状态和碰撞事件。渲染层只读取这些数据以及文字、配色和输出设置，不在绘图时运行物理世界。

例如，同一段 60 Hz 运动数据可以先导出 30 fps 的竖屏视频，再把标题改为英文、换字体、换颜色，导出 60 fps 版本。运动轨迹保持相同，新的画面需要重新绘制和编码。提高输出帧率不会自动提高原有物理数据的采样率；若需要更精细的数据，应提高 `simulation.sample_rate` 并重新模拟。

本地预览生成指定时刻的图片，完整导出生成 MP4、封面、分镜联系表和导出报告。圆环释放时的碎裂线段属于渲染效果；当前没有运行真实的碎片刚体模拟。声音来自程序合成的碰撞音效，没有自动生成配乐。

## 7. 先怎样做小规模内容试验

建议先用每种方案各 3 个版本比较。一次只改一个主要因素，例如标题、种子或释放时间，避免无法判断哪项影响了结果。先用低分辨率预览筛选，再导出正式版本。

可观察前几秒是否已经出现明显运动、累积段是否有变化、释放是否完整进入画面、文字是否遮挡主体、声音是否过密。发布后的完播率、重复观看率和互动表现，需要真实平台数据验证，程序本身不能保证流量或收益。

## 8. 本轮重新设计的两个首发方案

基于100条同类样本的机制统计，新增两个首发设计：

- [方案A：环形缺口逃逸·多层旋转缺口](../../../09_50x50扩展/scheme_A_ring_escape.md)：把圆环、缺口、逃逸和可见层数结合起来，强调空间悬念和结果追踪。
- [方案B：机械闸门·预装球·破碎多米诺](../../../02_项目方案/03_爽感解压动画/scheme_b_stack_domino.md)：把闸门释放、真实链式碰撞、玻璃破碎结合起来，强调规模增长和音画冲击。
- [两方案比较与实施顺序](../../../09_50x50扩展/two_physical_animation_schemes.md)。

两套设计已经接入工作台，模式名分别为 `ring_escape` 和 `stack_domino`。它们复用现有数据层、渲染层、字体/字号配置、事件音和导出验收流程；物理轨迹和渲染仍然分离，可以独立修改文字、颜色、尺寸和帧率。

## 9. 双通道指数赛 `versus`

### 视觉过程

两条完全相同的竖通道并排：左侧只有一颗球，右侧一开始就有一群球。两侧都靠接触分裂、都在同一套重力与弹性下弹跳，谁先把自己的通道填到设定容量，谁就赢。判定瞬间弹出终局卡，显示真实领先秒数，随后两侧底板同时打开、球一起漏出画面。

每次分裂移除原球，子球从原球旁边的环形空位冒出，半径在 0.24 运动秒内按 ease-out-back 曲线从 0 长到满径，同时叠加径向光晕与 0.09 运动秒的白光核心。默认触发约 0.06 秒顿帧，球位置、新生保护计时和出生动画一起暂停；同一物理求解子步中的分裂合并一次，至少运动 0.25 秒后才能再次触发。视频时间继续推进，因此顿帧会影响画面内的到线时间；只调整颜色或出生光晕不改变赛果。

初始球为第0代，子球比父球高一代。左侧默认绿色、右侧默认橙色，各自沿同一色系逐代变浅；同代使用同色。渲染按记录的代数与 `appearance.generation_fade` 混色，不在物理层保存逐球RGB，也不在绘图时重新计算分裂。

### 当前规则

- 通道几何、球半径、重力、弹性、摩擦完全一致；两侧起始球数、分裂子球总数和新生保护可以分别设置。
- 分裂数指子球总数，原球不保留：默认左侧1→4（净增3）、右侧1→2（净增1）。临近每侧容量上限时，最后一次只生成补足容量所需的子球。
- 每次有效碰撞检查分裂：两侧的左墙、右墙、地面、顶部，以及球与球的接触都可触发；球球接触中双方各自检查是否就绪。
- 初始球默认就绪，子球统一保护0.05运动秒，去掉长冷却与随机相位。保护期内正常参与碰撞；保护结束时仍接触就分裂，已分离则等待下一次实际接触。
- 判定使用Pymunk `pre_solve`，每个物理子步中持续接触也重新检查保护是否到期；不保存已经结束的碰撞供以后补发。待处理集合按原球ID去重，角落同时碰两面墙时每颗球也只替换一次。
- 外层保持120Hz推进，内部按 `ceil(max_speed / 120 / ball_radius)` 自动细分求解，默认最高速度900、半径5.5时为240Hz，半径3时为360Hz。每子步后立即处理分裂与顿帧，减少高速小球直穿或擦碰漏判；这是离散子步改进，不保证任意擦边碰撞都能捕获。
- 分裂点只取父球外圈 2–4 倍半径处的环形空位，找不到空位时取最宽敞的那一点让求解器挤开；不会退回到通道内任意位置，否则观众看到的是“瞬移”而不是“分裂”。
- 原球从物理空间移除并永久退役，子球使用新ID与下一代代数，满容量或开闸后不再分裂。顿帧期间运动时钟不推进，不消耗新生保护时间。
- 判定取两侧实际记满容量的时刻：`decided_at = min(left_full_at, right_full_at)`，领先秒数就是两者之差，没有任何脚本干预。
- 判定后按 `hold_after_decide` 倒计时开闸；若整段结束仍未分胜负，结果记为 `undecided`，终局卡显示“两侧都未能填满”。

### 调参建议

| 参数 | 作用 | 经验值 |
|---|---|---|
| `lane_capacity` | 每侧目标球数，决定“填满”的定义 | 600–700；两侧总目标容量不超过1500，生命周期槽另含退役原球 |
| `seed_balls` | 右侧起始球数，即标题里的对手数量 | 60–90，低于 30 会让右侧开场太稀 |
| `left_burst` / `right_burst` | 每次分裂后的子球总数 | 默认左4、右2；原球移除，净增分别为3、1 |
| `left_cooldown` / `right_cooldown` | 两侧子球的新生保护，运动秒计时，不随机错峰 | 默认均为0.05秒；增大会让保护期内的碰撞不立即分裂 |
| `first_split_at` | 左首球保护延迟，不影响右侧初始球 | 默认0，范围0–12运动秒；0表示首球就绪 |
| `hold_after_decide` | 判定到开闸的间隔 | 1.5–3，留出读终局卡的时间 |
| `split_hitstop` | 分裂顿帧的视频时长 | 默认0.06秒，范围0–0.2；0关闭 |
| `split_hitstop_interval` | 两次顿帧之间至少经过的运动时间 | 默认0.25秒，范围0.1–2；密集分裂共用节奏 |
| `appearance.palette[0/1]` | 左右初始基色 | 默认绿色 / 橙色；改色不重算物理 |
| `appearance.generation_fade` | 每代向浅色推进的强度 | 默认0.2，范围0–0.6；0关闭代际变浅 |

分裂总数、新生保护、顿帧和种子都会影响真实结果；改变规则后需要重新模拟，不能保证旧样片的反超结果仍然出现。可更换参数持续生成比赛，标题中的胜负与领先时间应以导出结果为准。碰撞触发修正版保存在 `outputs/versus_collision_fix/`，先前样片保留在 `outputs/versus_split_v2/` 与 `outputs/versus_demo/`。

## 10. 后续可扩展方案，当前尚未实现

| 方向 | 新的观看期待 | 需要补充的能力 |
|---|---|---|
| 彩球分类、落入同色容器 | 混乱逐渐归位 | 多容器几何、目标判断、完成状态 |
| 多米诺连锁 | 触发能否一直传到终点 | 矩形刚体、关卡布局、链式完成检测 |
| 软体挤压、切割泡沫 | 挤压变形与切面释放 | 软体或粒子模拟、新材质渲染 |
| 磁力聚散、粒子成字 | 无序粒子逐渐形成图案 | 受力场、文字轮廓采样、目标轨迹 |
| 无缝循环 | 结尾自然回到开头 | 首尾状态约束、循环音频、连续性校验 |

这些方向可以继续复用配置、数据保存、文字渲染和导出流程；物理机制仍需要单独实现。涉及高质量软体、三维材质或生成式画面时，再评估 Blender 或 GPU 工具。当前六个方案没有必要连接远程 4080 SUPER 才能运行。
