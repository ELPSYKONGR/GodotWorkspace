# 项目技术决策与已解决问题

## 固定运动数据，独立绘图

2026-11-11：采用 Pymunk → SceneData NPZ → Pillow/FFmpeg 的数据流。运动采样率与输出帧率分开，默认保存 60Hz 数据。改文字、字体、字号、配色、分辨率、输出帧率和音量不重算物理。改变时长、种子或物理参数才生成新数据。低采样率导出更高帧率会重复采样，不能凭空增加运动细节。

`render --scene` 只加载数据与渲染模块，不导入 Pymunk。已保存数据中的模式、球半径和释放时刻优先于当前配置，防止逃逸轨迹配上完整圆环。时长不匹配则拒绝导出。

## 保持安装与产物在项目盘

运行时、环境、uv 缓存、临时目录、轨迹与产物均通过工程相对路径定位。系统字体只读取，不复制到项目。安装脚本禁止注册全局 Python；审计工具使用显式的项目内缓存目录。复制工程到其他机器时重建 `.runtime`、`.venv`，不复制带有原路径的虚拟环境。

## 校验边界

文字模板只允许有限的计数与时间变量，禁止任意属性访问、格式扩展和字体路径。字体来自系统或 `assets/fonts` 的 ID 列表；换机器后应重新选可用字体。文字越界会明确报错，不自动缩小或截断。动态计数变宽也可能造成后续帧越界，排版时需预留空间。

轨迹使用 `allow_pickle=False` 的 NPZ，加载时检查坐标、计数和事件一致性。损坏缓存直接报错；确认不再需要后可移除对应 `.cache/scenes/<key>.npz`，再生成。更改物理算法时应更新缓存键中的 schema 版本，避免复用旧算法结果。

## 依赖审计与命令行编码

Pillow 12.3.0 在审计时报告已知漏洞，已升级到 13.0.0，并重新验证文字绘图与实际编码。审计报告只代表检查时依赖数据库的结果。

Windows 上脚本显式使用 UTF-8 读取 JSON；启动器设置 `PYTHONUTF8=1`，避免中文标题和工程路径因系统默认 GBK 产生异常。FFmpeg 编码后执行完整解码；其 stderr 管道在读完后关闭，避免资源泄漏。
