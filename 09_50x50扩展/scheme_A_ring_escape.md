# 方案 A：环形缺口逃逸·多层旋转缺口

这是从样本中“圆环、缺口、逃逸、可见进度”机制重新设计的 19.6 秒竖屏物理动画。观众始终知道目标是逃出，但不知道下一颗球能否抓住缺口，因此每次靠近缺口都会形成一个短悬念。

## 核心观看规则

画面中心有 12 个同心环，每个环都是由碰撞线段组成，并保留一个随环体旋转的真实空段。12 颗球从内层向外运动；球只有在球体和环体发生几何穿越后才计入 `ring_pass`。环半径固定，缺口由运动学环体驱动，避免把球或边界瞬移到新位置。

每颗球有 `energy`、`speed`、`ring_index` 和稳定 `ball_id`。撞环的实际冲量会消耗能量；能量低于 25% 时进入警示状态，归零记为 `fail`，越过最外环并离开边界记为 `escape`。全部球完成或失败后进入 `result`；若片段结束时仍有球在场，结果明确标记为 `incomplete`。

规则必须由数据层记录，渲染层不能根据画面猜事件。建议数据结构如下：

```json
{
  "schema": "ring_escape.v1",
  "seed": 24017,
  "output": {"width": 1080, "height": 1920, "fps": 60, "duration_s": 19.6},
  "ball": {"radius": 25, "speed": 330, "energy": 100, "max_speed": 620},
  "rings": [{"id":"r01", "radius":610, "gap_center":0.3, "gap_width":0.34, "angular_speed":0.65}],
  "events": [],
  "result": {"status":"pending", "reason":null, "time_s":null}
}
```

事件包括 `collision`、`ring_pass`、`energy_low`、`escape`、`fail` 和 `result`；每个事件由物理步进产生并记录时间、球 ID、环索引和原因。固定随机种子后，同一数据输入必须生成相同轨迹。

## 四层实现

**数据层**生成球、环、状态机和事件时间线，保存位置、速度、颜色、剩余层数和结果原因。应同时保存 120 Hz 物理轨迹与 60 fps 输出配置，让换字体、改文字、改尺寸时无需重算物理。

**物理层**使用 Pymunk。每个环由连续碰撞段组成，缺口使用真实几何空段，环体以运动学角速度驱动；采用 1/120 秒固定步长，碰撞反弹由 Pymunk 求解。穿环判定使用连续采样的球心半径阈值，避免单帧跳过环体。速度超过配置上限时限速，退出或能量耗尽后立即关闭该球的碰撞体。

**渲染层**只读取轨迹和事件。中心构图使用 1080×1920，安全区内放标题和 HUD：标题 48 px、HUD 32 px、结果 68 px、环线 12 px、球半径 25 px、拖尾 14 帧。颜色只承担语义：青色为可行动球，橙色为低能量，红色为失败，白色为当前目标环。字体、字号、文本、帧率、颜色、拖尾和结果停留时间都放入 JSON。

**音频层**从事件表生成短音：碰撞 35–70 ms、穿环上行音 120 ms、低能量提示两音、失败下坠音、成功亮音和结果确认音。没有逐条试听参考样本时，不能宣称音色已验证；制作时必须以事件时间戳合成，不能按帧数猜测。

## 19.6 秒分镜

| 时间 | 画面事件 | 留存目的 |
|---|---|---|
| 0–0.7 s | 3 颗球和 12 层环立即出现，第一颗球撞环 | 首屏直接给规则与运动 |
| 0.7–2.5 s | 缺口旋转，第一颗球错过后再次接近 | 让观众理解“不是自动通过” |
| 2.5–6.0 s | 逐层通过，HUD 显示 11/10/9 层 | 形成可读进度 |
| 6.0–9.5 s | 多个环体继续转动，出现低能量球 | 施加受阻与反转 |
| 9.5–13.8 s | 4–8 层连续穿环，每次穿环短暂停顿 | 形成连续爽点 |
| 13.8–16.8 s | 剩余 4 颗球争夺最后两层 | 让结果变得不可预测 |
| 16.8–18.4 s | 最后一环打开一次，成功/失败状态锁定 | 回答标题问题 |
| 18.4–19.6 s | 结果卡片和 0.4 秒可循环过渡 | 让结尾完整且便于循环 |

## 关键验收指标

- `max_event_gap_s <= 1.4`，中段不能出现长时间无进展；若没有进展，必须如实显示仍在碰撞等待。
- `ring_pass_count == result_layers` 时才显示成功。
- 结果出现前最后一个可见球必须仍在画面内，尾段不留空。
- 球体与环无穿透；角速度、速度和能量均在配置范围内。
- 30/60 fps 导出使用同一轨迹时，事件时间误差小于一帧。
- 标题、HUD 和结果卡片无越界、无遮挡；字幕字号可独立修改。

## 自动化、成本和难度

MVP 可在现有 D 盘 Python 工作台中实现：新增 `ring_escape` 数据生成器、事件校验器和一份渲染预设即可。生成 20 秒 1080×1920/60 fps 的 CPU 成本约 2–8 分钟；若使用现有渲染层，单集直接成本主要是电费和人工，约 1–5 元电费，人工首版约 0.5–1.5 小时，批量稳定后可降至每集 5–15 分钟人工复核。Pymunk、NumPy、Pillow、FFmpeg 均可使用已有开源依赖。

自动化流程：读取主题和难度 → 固定 seed 生成轨迹 → 运行无穿透/结果/事件间隔 QA → 渲染低清预览 → 通过筛选后输出 1080×1920 → 事件音合成 → 生成封面、文件哈希和报告。难度为中等，主要风险是缺口穿越判定、运动学环体速度和结果兑现。

## MVP 顺序

1. 先实现 3 层环和 3 颗球，验证缺口穿越与 `ring_pass` 事件。
2. 扩展到 12 层，加入低能量和失败状态。
3. 加入 HUD、事件音、结果卡片和循环尾帧。
4. 用 10 个 seed 批量生成，按事件间隔、无穿透和结果完整度筛选。
