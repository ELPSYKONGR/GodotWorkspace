# 50×50同类型解压动画：逐条分析框架

本框架供 `analysis_50x50.md` 的100条作品统一使用。它把页面可见事实、视频中直接可观察的事实、设计推断和自制实现建议分开，避免把“看起来可能有效”写成已经被播放数据证明。

## 1. 每条作品的最小记录

每条必须先填下面的元数据，再写设计分析：

| 字段 | 内容 |
|---|---|
| 平台和作品ID | B站 BV号或抖音视频ID；原始页面链接 |
| 标题、账号、发布时间、时长 | 按页面/API保存，抖音显示“万”时保留原字符串 |
| 播放、点赞、评论、收藏、分享 | 分开记录；抖音播放未公开就写 `null`，不从点赞反推 |
| 指标快照时间与来源 | API地址或页面快照文件 |
| 下载状态 | 已下载、仅证据、失败；注明公开播放流不等于创作者母版 |
| 页面证据 | DOM/页面快照、截图、抽帧、媒体文件、manifest |
| 观看范围 | 完整观看、时间区间抽看、只看截图；是否听验声音 |
| 证据置信度 | A=媒体已下载并至少看首中尾；B=媒体/抽帧看过但未完整看；C=只有页面标题、截图或简介 |

## 2. 视觉整齐度

“整齐”不是越简单越好，而是视觉层级和规则是否容易读。每条按1–5分记录，并写事实依据：

| 维度 | 1分 | 3分 | 5分 |
|---|---|---|---|
| 主体层级 | 主体、文字、弹幕和背景互相抢注意 | 主体可见，局部有遮挡 | 主体、目标、状态信息一眼可分 |
| 对齐与间距 | 随机拥挤或边缘被切 | 大体居中，个别重叠 | 轨迹、环层、文字和计数有稳定网格 |
| 几何一致性 | 半径、线宽、颜色反复跳变 | 大部分一致 | 同类对象尺寸、线宽、颜色语义稳定 |
| 对比和可读性 | 目标融入背景 | 能看懂但细节弱 | 背景、主体、目标和结果有清楚对比 |
| 画面安全区 | 关键对象贴边或被平台UI挡 | 偶尔靠近边缘 | 竖屏裁切、标题和字幕都留有安全边界 |
| 密度控制 | 一开始就满屏，事件不可追踪 | 密度变化可见但局部拥挤 | 从稀到密、从密到清空的变化有阶段意义 |

记录格式：`事实：主体位于画面中央/环间距大致一致；推断：因此目标球容易被追踪；待验证：弹幕覆盖时是否仍清楚。`平台弹幕不能误当作者字幕。

## 3. 运动流畅度

从下载的视频或抽帧中记录：首个变化时间、碰撞频率、速度变化、残影、边界接触、镜头/相机变化和结尾状态。若只有截图，写“无法核验”，不要凭单帧声称流畅。

| 检查项 | 需要观察的事实 | 自制实现验收 |
|---|---|---|
| 帧节奏 | 是否掉帧、突然跳位、碰撞后反弹是否连续 | 固定数据层轨迹，30/60fps渲染位置连续，导出无重复帧 |
| 速度曲线 | 匀速、加速、减速、弹性、停顿是否有意图 | 关键事件使用可解释的速度/缓动，不能用随机抖动代替变化 |
| 碰撞可信度 | 接触点、反弹方向、穿透、重叠是否明显 | 记录碰撞事件和法线；离散步长不能导致穿透或重复触发 |
| 拖尾与模糊 | 是否帮助方向判断，是否盖住主球 | 拖尾来自轨迹历史，长度和透明度可配置 |
| 进展连续性 | 目标数量、环层、线条或门是否按事件变化 | 每个状态变化都有事件记录，不能只在结尾强行改状态 |
| 结束处理 | 是否出现无球尾段、硬切、最后结果不清楚 | 数据层给出 `result_time` 和 `result_reason`，再决定剪辑或循环 |

推荐量化字段：`first_event_s`、`event_count`、`max_event_gap_s`、`last_visible_object_s`、`result_time_s`、`frame_rate`、`dropped_frame_count`。这些是作品本身的工程指标，不是平台留存指标。

## 4. 声音和事件配合

只有实际听到音轨或导出文件存在时，才写“听到某种音效”。只看到页面播放器静音图标时写“声音状态未知”。逐条记录：

- 碰撞、增殖、吞噬、突破、淘汰、释放、结果是否有对应短音。
- 声音起点与画面事件的相对延迟，是否过密、遮蔽或疲劳。
- 背景音乐、低频、提示音和最终结果是否有层级。
- 是否存在静音版、平台二次配乐或音频不可访问。

自制实现应使用事件总线：`collision`、`spawn`、`consume`、`escape`、`line_transfer`、`ring_break`、`gate_open`、`result`。音频层读取事件时间戳生成短音，数据层不依赖音效才能完成物理。建议先做有声/静音AB，再调音色和音量；不能根据点赞数据单独推断声音造成留存。

## 5. 有效机制和观众心理路径

每条都按“规则→目标→进展→受阻/反转→结果”写五句话：

1. **规则**：首屏能否用一句话解释？触发是碰撞、时间、数量、颜色还是位置？
2. **目标**：观众要等什么——逃出几层、清空多少、谁留到最后、是否到达中心？
3. **进展**：剩余层数、生命线、累计数、填充高度、颜色阵营或阶段边数是否可见？
4. **受阻/反转**：缺口错过、边界收缩、资源被抢、冻结、随机门、吞噬或分裂是否有可理解原因？
5. **结果**：标题问题是否被真实回答？结果是否保留足够时间让观众看清？

这五句话比“很解压”“很爽”更适合转成数据层和渲染层任务。

## 6. 抓人眼球、注意力留存、观众期待

不能把公开播放量当作完播或留存。分析时只写设计上的可观察线索，再提出待验证指标：

### 首屏0–2秒

- 首帧是否立刻出现主体、目标、强对比颜色或即将发生的事件？
- 标题是否给出一个可判断的问题，而不是只有“解压”“太爽”？
- 首次碰撞、增殖、逃出、破环或释放发生在几秒？只有截图时记为“无法核验”。

### 中段留存

- 事件之间最长无进展间隔是多少？
- 是否每隔一段时间改变一个维度：球数、速度、环层、缺口、生命线、边数、阵营或密度？
- 观众是否要追踪一个主球、一个出口、一个剩余数字或一条颜色阵营？
- 是否存在“差一点成功”的可解释受阻，而不是无目标等待？

### 期待与结果

- 规则让观众可以预测下一步，但不能提前知道全部结果。
- 夸张数字、倒计时和“能否”问题必须在结尾兑现；若未完整看结尾，不能写“已兑现”。
- 结果字幕只显示真实结果，例如“39/48通过缺口”；不能把定时全开写成自然溢出或全部逃逸。

可由自有发布后台验证的指标：2秒/3秒留存、平均观看秒数、分段退出、完播率、重复观看、评论中的规则理解、分享和收藏。AB测试必须一次只改一个变量。

## 7. 对象机制词典

### 7.1 球、圆点和小球群

- **碰撞反弹**：速度、法线、摩擦和边界决定轨迹；爽点来自可预测但不完全可知的下一次接触。
- **增殖/翻倍/分裂**：碰撞、压缩、活塞或概率触发新球；必须显示真实触发条件和数量上限。
- **吞噬/消除**：大球、砖块、白球或同色规则移除目标；把剩余数或清空条件写在画面上。
- **逃逸/到达**：球通过缺口、中心、层级出口或玻璃目标；记录通过次数、失败和剩余障碍。
- **堆积/重力/溢出**：球在容器中累计，目标线或容量触发释放；“定时释放”和“真实溢出”必须分开。
- **身份/阵营**：颜色、编号、图标或唯一主球承担追踪和站队；不应让所有球同等抢注意力。
- **时间状态**：冻结、回溯、加速、缩小、倒计时和生命时长；时间窗必须可读。

### 7.2 线条、连线和绳索

- **生命线/资源线**：球拥有同色线，线被抢走或耗尽即淘汰。
- **连接网络**：线连接球、节点或边界；断线、合并、分裂、颜色转换可作为阶段事件。
- **路径/轨道**：线规定球的可行路线或出口，路径开闭制造选择与受阻。
- **扫线/光束**：移动线切割、扫描、激活或消灭对象；要显示扫描方向和触发窗口。
- **拉伸/弹性绳**：长度、张力和回弹形成运动；可用线长度和张力作进度读数。
- **整齐度要点**：线宽、端点、交叉层级、色彩语义和节点间距要一致；避免线条互相覆盖造成规则不可读。

### 7.3 圆、圆环和同心环

- **边界容器**：圆限制运动，缺口是出口；圆心、半径和边界厚度必须稳定。
- **缩小/扩张**：半径或环间距变化制造时间压力；显示剩余层或倒计时。
- **多层突破**：每破一环才获得下一层目标；复原时间窗制造“差一点”。
- **旋转缺口**：缺口角速度、宽度和球速共同决定通过概率；记录每次尝试结果。
- **同心图案**：密度、颜色和旋转变化可以带来秩序感，但不能遮住主球和目标。
- **波纹/脉冲**：碰撞向外传播，视觉上把一次事件放大；不要把装饰波纹误当成实际判定。

### 7.4 长方形、方块、砖块、条带和门

- **挡板/活塞**：移动方向、速度、周期和碰撞后果；活塞可以触发翻倍或改变轨迹。
- **砖块/目标墙**：按颜色、编号或耐久度消除；每次破坏应有真实剩余量。
- **滑动门/矩形缺口**：开一门关一门、周期性通道和选择路线；门状态要可见。
- **容器/平台**：矩形底部、斜面、传送带和边界形成堆积、弹跳或溢出；注意重力和遮挡。
- **网格/拼图**：方块填充、消除、三消和行列变化；进度可用剩余格数或完成行数。
- **整齐度要点**：直角、间距、边框线宽和对齐比随机旋转更容易让观众识别状态；变化应集中在一个明确维度。

### 7.5 多边形、星形和不规则边界

- **边数升级/减少**：每几次碰撞增加或减少一条边，形成阶段节点。
- **角点反弹**：角度和边长改变反弹路径，带来轨迹差异；需避免离散碰撞穿透。
- **形状生存赛**：不同多边形作为阵营或容器，最后留下的形状即结果。
- **旋转多边形**：旋转速度与缺口共同产生逃逸窗口；边数和剩余层数应可读。
- **不规则迷宫**：边界复杂时要降低球数和文字密度，否则观众无法判断碰撞原因。

### 7.6 粒子、碎片、光点和烟雾

- **爆发**：碰撞后从少量对象变成大量粒子，形成规模反差；结果应有数量或持续时间边界。
- **流场/雨/喷射**：粒子方向、密度和容器容量形成连续运动；入口和出口要清楚。
- **消散/聚合**：粒子被吸收、合并、结块或转成球；变化要对应事件。
- **装饰粒子**：星尘、光晕和残影只承担氛围；不能和可判定目标使用相同视觉权重。

## 8. 实现过程：数据层、渲染层、音频层

每条作品的“实现建议”至少包含：

1. **数据层**：固定随机种子；稳定对象ID；形状参数；初始状态；事件时间线；目标、进度、受阻和结果原因；导出JSON/NPZ。
2. **物理层**：碰撞检测、边界、重力/阻尼、速度上限、生成/吞噬/淘汰、环/门/线条状态机。物理时间步长和渲染帧率分离。
3. **渲染层**：背景、几何对象、颜色语义、线宽、拖尾、文字、计数、结果卡片；字体、字号、布局、内容和30/60fps可配置。
4. **音频层**：从事件时间线生成碰撞、突破、消除、释放和结果短音；支持静音、音量和音色配置。
5. **验收层**：指标与标题一致；对象不穿透；进度不长时间停滞；结果真实可见；最后无球尾段可裁；编码和音画同步通过检查。

- 观看范围与置信度：A/B/C；是否试听：
- 主要对象：球 / 线条 / 圆环 / 长方形 / 多边形 / 粒子 / 混合

- 目标与结果条件：
